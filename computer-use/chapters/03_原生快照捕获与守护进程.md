# 原生快照捕获与守护进程

## 地址与证据解释

本章所有0x100…地址均为当前样本ARM64 slice未滑移虚拟地址，不是运行时ASLR地址。整个helper是universal Mach-O；不能把旧0.4.153地址沿用。section内slice文件offset=section.offset+VA-section.address；fat文件offset还要加slice fat_offset。当前ARM64 slice从fat文件byte1228800开始；本章__TEXT范围可用VA−0x100000000再加1228800。

结论来自指令、分支和调用数据流，不仅是strings/symbol名字。自动ADRP/ADD注释不是完整数据流，某些stale-register字符串注释可能错误；只有人工核对的常量进入已证结论。本章以SNAP指analysis/native-snapshot/FINDINGS.md，NATIVE指analysis/native/FINDINGS.md。本整合包另附 .153 的有界原始反汇编节选；本章 .164 地址仍按其自身样本解释，不将 .153 地址或行为无条件迁移。本章提供原创描述和地址范围，以便持有同 hash 官方样本的人复核。

## Unix socket 服务

Daemon.run位于0x100073f6c。先建socket父目录，中间目录创建错误被吞；unlink现路径，创建AF_UNIX/SOCK_STREAM。UTF-8路径长度≥104 bytes时拒绝并close。bind使用106 bytes sockaddr_un，socket chmod0600，listen backlog4。随后启动idle timer、异步accept loop、signal handlers和main RunLoop。[SNAP §1]

handleQueue明确为concurrent（0x100073b70），accept到每个peer后异步分派。因此不同连接可并发；单连接的行按同步processLine顺序处理。不能把客户端pending map的并发或单peer串行误写成全局动作队列。

原创循环：

    buffer = 空bytes
    重复:
        n = recv(fd, scratch8192, 0)
        n == 0: 结束
        n < 0且errno==EINTR: 重试recv
        n < 0的其它情况: 记录并结束
        append scratch[0:n]
        当buffer含LF:
            取LF前的bytes并删除该前缀和LF
            空行则continue
            response = 同步processLine(line)
            context.send(response + LF)
    context.teardown(); close(fd)

此循环未见最大累计行长、CR剥离、timeout取消检查或EOF尾巴处理。peer在同步dispatch中断开，此层不会取消当前dispatch；直到回到recv才观察断开。此结论仅限socket层，不代替每个异步子系统分析。[0x10008ab80、recv0x10008abdc、dispatch0x10008acf0]

processLine先更新lastActivity再decode JSON，坏JSON也可刷新idle。使用JSONDecoder/Encoder，encoder withoutEscapingSlashes。成功按原id封装；CUError按其错误封装，其它异常转internalError(localizedDescription)。decode错误使用id="?"与invalidArg。encoder失败有硬编码fallback，精确值已由后文“原生 wire 编码精确契约”闭合：{"ok":false,"error":{"code":"internal","message":"encode failure"}}，不含id，writer再加LF；JSON一般字段顺序仍不保证。[0x100075e98–0x100076260]

ConnectionContext.send异步排写、检查weak context/alive/daemon、writeLock内循环直到全部bytes写出，EINTR重试，同peer的JSON不会因短写而交错。teardown仅alive=false、取消Appshot subscription tokens并清集合；没有回滚动作、清AX ref或清mapping。

## idle 生命周期

native构造缺省idle为600s；MCP/host spawn显式传900s，两者都必须记录。main queue timer从now+30s开始，每30s检查。若BareModifierMonitor.currentHotkeyName非nil，刷新lastActivity并返回；否则仅当now−lastActivity严格大于idleTimeout且非shuttingDown才退出。

退出顺序：设isShuttingDown、AXBridge.restoreAllEnhancedUI、close listen fd、unlink socket、exit(0)。这不是保证所有peer请求drain完的优雅停机。多个peer的snapshot可交错beginSnapshot/register；store局部锁不等于整个snapshot事务锁。safe版增加同资源串行lane要记为偏离。[0x100073bf4、0x1000749f8、0x100083214]

## get_app_state 原生默认与顺序

native参数：bundle可选string，pid可选Int32，window_id可选UInt32；depth6；interactive_only=true；screenshot_max_width=1600；include_screenshot=true；auto_launch=true；wakeup_seconds=1.5；disable_diff=false；screenshot_path可选，否则用毫秒timestamp加.jpg。

普通MCP强制max width默认1280，不等于native1600；sky/host是否传值必须按各入口契约判断。native部分转换使用checked integer conversion，负window_id/超UInt32或超Int32 PID可能trap，不能承诺都是整洁error。safe版应显式校验并标记修复。[SNAP §2，0x100077cfc–0x100078e90]

执行顺序：

1. auto_launch允许、给了bundle而没pid、bundle未运行时，launchWithFrontmostPreserved并waitUntilReady
2. 调AXBridge.snapshot，传depth/filter/wakeup预算
3. include_screenshot=true时找到被选AX window并unminimizeIfNeeded；若真的恢复最小化，再用wakeupSeconds0重snapshot，成功才替换原snapshot，失败吞掉
4. snapToDictDiffed先更新diff基线，能获取时附menu_shortcuts
5. 只有include_screenshot且snapshot.windowId存在才抓图
6. capture失败仅附screenshot_error，AX结果仍成功，且diff基线已更新
7. capture成功并有bounds才写mapping，再判断原始AX元素个数是否触发OCR

因此观察状态可能恢复最小化窗口，不能笼统承诺“纯读取、绝无可见UI变化”。捕获失败也不回滚diff。

## direct snapshot 与 depth0 的区别

native另有cmd字面量为snap的分支（函数名snapshot与wire command snap不可互换）：AXBridge.snapshot后调用plain snapToDict，不经过AppStateDiff。default depth6、interactive filtertrue、wakeup0。[0x10007735c、0x100077380]

direct snapshot(depth0)会beginSnapshot、清当前代ref集合/剪无效条目，可只处理root；它不更新diff基线，也不凭snapshot更新截图mapping。显式get_app_state(depth0)则经过diff，且可以抓图、覆盖mapping/OCR。普通MCP动作后补图调用的是get_app_state(depth0)，不是上述direct snapshot。必须按实际cmd区分，不能把两者都简称“浅快照”然后推同一状态副作用。

## AX window 选择

snapshot入口先AXIsProcessTrustedWithOptions，resolve app，enable enhanced UI，建立now+wakeupSeconds deadline，并且只调用一次beginSnapshot。

window选择函数0x100012774：若requestedWindowId存在且找到匹配，取第一个匹配；没匹配不报错，继续第一个focused；再没有则windows[0]。因此无效window_id可能观察另一个window。AX window枚举失败或空时，用WindowList.topWindow(pid)补metadata，但AX输出保持空。AXWindows枚举原序及字段默认已在后文“AX window 枚举与属性取值细则”闭合；剩余未知是CG fallback完整选择/排序和OS动态语义，不能用常识自填。[SNAP §3]

## AX 树遍历

walk位于0x1000128e4，preorder DFS，按AXChildren原序。先取role（失败为空串）、actions、children。interactive = actions非空 或 role在16类集合。filter只控制是否输出当前节点，不挡子树；它不是enabled且interactive。即使remainingDepth0也先读children、处理当前节点，再停止递归；负深度同样先处理当前节点。

16个role：AXButton、AXCheckBox、AXRadioButton、AXPopUpButton、AXMenuButton、AXMenuItem、AXTab、AXLink、AXTextField、AXTextArea、AXComboBox、AXSlider、AXIncrementor、AXDisclosureTriangle、AXCell、AXRow。禁用控件仍可能被输出。descriptor/recovery的200节点上限不适用于该snapshot walk。

原创伪代码：

    walk(element, remainingDepth, parentRoles):
        role = 尝试读AXRole，否则空串
        actions = copyActionNames(element)
        children = 尝试读AXChildren，否则空数组
        interactive = actions不空 或 role属于16角色集合
        if not interactiveOnly or interactive:
            读取其余序列化字段
            descriptor = 当前属性与受限parentRoles
            ref = store.register(element,pid,snapshotId,descriptor)
            out.append(当前element record)
        if remainingDepth - 1 < 0: return
        for child in children的原序:
            walk(child, remainingDepth - 1, parentRoles+[role])

SerializedElement输出keys和缺省省略规则已在第二轮闭合，见后文；真实AX属性来源强转和异常仍须独立验证。实现必须把未知属性处理分支列到STOP矩阵，不可声称该伪代码已覆盖所有AX异常。[SNAP §3、§7]

## 唤醒重试

第一次walk输出>1元素时ax_status=populated，attempts1，wakeup_duration_ms0。否则deadline仍有预算时最多三次重试，sleep计划为0.15、0.25、0.4秒，每次取计划值与剩余非负deadline的较小者。每次重新enable enhanced UI、清out、枚举选择window、walk，但不再次beginSnapshot，因此currentSnapshotRefs在同代重走中影响ref复用。

重试成功状态woke_up；最终低元素输出若预算≤0为no_wakeup_budget，否则empty_after_wakeup。attempts含初始，最大4。duration是用monotonic uptime测量的sleep累计、整数除1000000，并非AX遍历总体耗时。用真实总耗时对该字段作相等断言会误判。[0x100011e10、0x10008f088、0x100012230]

## 状态输出与 diff

snapToDict输出snapshot_id、ax_status、wakeup_attempts、wakeup_duration_ms、app{bundle,name,pid}、window{id,title,bounds}、elements。bounds使用x,y,w,h。SerializedElement可选字段已闭合为缺省省略，见后文；SnapshotResult各层可选值需分别按WIRE契约核对，不把element规则扩大到所有容器，JSON字节顺序不保证。

snapToDictDiffed先把全量SerializedElements转dict，按PID/window key应用diff，再替换elements为变化项，并加elements_are_diff、unchanged_element_count；removed_refs非空才附。disable_diff=true仍更新基线。OCR门槛用原始SnapshotResult.elements，不用这个差分数组。差分详细算法在输入/状态章。

## ScreenCaptureKit 抓图

get_app_state capture closure0x100082650直接尾调Capture.captureWindow0x10003f738，不先走captureWindowFast。解析SCWindow依赖异步shareable cache，第二轮已闭合refresh/失效策略，见后文；await取消与OS时序仍未证；没有SCWindow时internalError。

窗口抓图配置：desktopIndependentWindow filter；scale取NSScreen.main.backingScaleFactor或2.0，注意不是目标window所在screen的scale。pointW/H至少1，pixelW/H=Int(point×scale)向零截断；若maxWidth≥1且小于pixelW，width=maxWidth，height=max(1,Int(oldH×maxWidth/oldW))。cursorfalse，audiofalse，macOS≥14 ignoreShadowsSingleWindow，minimum interval1/60s。

已检查路径仅macOS≥14调用SCScreenshotManager.captureImage；较老分支抛internalError，不是已证fast fallback。因此helper minOS13不等于这条截图路径在13可用。写JPEG quality0.85，返回实际CGImage宽高。[0x10003f8c0、0x10003fafc、0x10003fbf0、0x10003fd64]

## mapping 的发布与陈旧风险

仅成功截图且snapshot.windowBounds存在才写lastMapping[pid]，数据是AX snapshot window的point origin/size、实际图像pixelW/H和windowId。图像尺寸来自SCWindow/CGImage，point bounds来自AX，两源可能不一致，需运行校准。

desktopX=originX+screenshotX×pointWidth/pixelWidth；desktopY=originY+screenshotY×pointHeight/pixelHeight。translate函数按PID查找并锁mapping，无clamp/expiry。失败截图、未抓图、缺bounds、direct snapshot都不改旧mapping。已检查xref未见TTL/window close/app exit独立失效，因此旧mapping可留到daemon结束或同PID覆盖；PID复用是额外风险。[0x1000790b0、0x100082890]

settlePrelude也优先取lastMapping[pid].windowId，缺失才topWindow，并计算cheapWindowPixelHash。因此陈旧mapping不仅影响点击坐标，还影响动作后的settle观察window。

## OCR 是内部可达回退

成功get_app_state截图后，原始AX elements.count≤1才VisualIndex.index(path,maxResults80)。不是“diff只剩一项就OCR”，不是include_screenshot=false也OCR，更不是公开MCP OCR工具。[0x1000790c4–0x1000790e0]

VisualIndex先读磁盘图像实际W/H，VNRecognizeTextRequest recognitionLevel1（fast）、languageCorrection=false、languages en-US/zh-Hans。按Vision observation原序取topCandidates1，跳无candidate和空text；检查路径未见confidence阈值/排序。接受计数从0开始加，生成v+十进制计数；保留text/confidence；达到maxResults停止。载图/Vision失败返回空regions。

Vision左下normalized bbox(x,y,w,h)转截图像素左上：x'=x×W，y'=(1−y−h)×H，w'=w×W，h'=h×H。例如W1000、H500、bbox(0.1,0.2,0.3,0.1)得到(100,350,300,50)。此bbox不能直接当桌面point。

regions非空才替换visualRefs[pid]，输出visual_regions{ref,text,bounds{x,y,w,h},confidence}。v编号每次index重置，表按PID。空OCR、跳过OCR、抓图失败不清旧表；xref未找到独立expiry。因此旧v1可能仍指旧图上的框，新一次非空index又可能把v1改为另一个文字。这不是与AX eN同一种稳定身份。[SNAP §6]

## 原生 wire 编码精确契约

Request的id、cmd必需String，数值JSON-RPC式id不接受；args可省略或null，两者转no args；若给数组/非object，Request decode失败；未知top-level key由合成keyed decoder忽略。缺id/cmd、类型不对、坏JSON都走同decode失败路径，返回id="?"，不是提取一半原id。[WIRE §Request，0x100008294]

成功为{id,ok:true,data}，error省略。即使成功值nil也编码为data:null，不省data。失败为{id,ok:false,error:{code,message,hint?}}，data省略，hint不存在则省略。常规error不在top-level。字段顺序未要求sortedKeys，不承诺JSON byte顺序；withoutEscapingSlashes启用。

malformed响应error.code=invalid_arg，message前缀为malformed JSON: 后接Foundation localizedDescription，尾部依平台/语言，不要伪造固定英文。编码失败应急值精确为{"ok":false,"error":{"code":"internal","message":"encode failure"}}，没有id；writer再加LF。[0x100095610]

AnyCodable decode依序尝试null、Bool、Int（ARM64 signed64）、Double、String、递归array、递归String-key dict；所有尝试失败时值nil而不是重抛最后错误。数组null成员和object null value均保留。encode先nil→null，再识别CFBoolean，避免Bool变1/0；NSNumber按objCType整型codes转Int，其余转Double；再typed Bool/Int/Int64/UInt32/Double/Float/CGFloat/String；array/dict递归；其它对象用String(describing:)编码string，不泄露任意对象内部JSON结构。[WIRE §AnyCodable]

Args helpers：str仅String cast；int依序Int、Double向零截断、带符号十进制String，Double非finite/越界可能trap；double接受Double、Int、String数值；bool接受Bool再Int!=0，不解析"true"/"false"字符串。缺args/key/null都返回nil。新实现若防trap，必须记为安全偏离。

## 应用解析和视觉 ref 目标

AXBridge.resolveApp优先有效PID对应NSRunningApplication；PID无效且bundle存在时，先bundle ID的runningApplications第一个，再localizedName与bundle字符串精确相等的第一个；都失败appNotFound。有效PID和bundle不一致时PID获胜且不交叉校验；两者都没给不会取frontmost，而是报pid=0描述。[0x100019718]

v开头ref点击走visual cache，必须通过pid/bundle resolveActionPid，缺目标invalidArg；按visualRefs[pid][ref]查CGRect，缺ref elementNotFound；取截图像素bbox中心，再用该PID当前mapping转桌面point，缺mapping为internalError。由于visual cache和mapping可分别陈旧/更新，同PID可能混用两代。普通MCP ref分支只转ref不转bundle/PID，因此普通MCP即使接收ref=v1加bundle，ref分支丢掉bundle/PID后仍在native失败为invalid_arg，发生在visual cache lock之前；sky索引状态只读raw.elements、不读visual_regions，也没有把OCR框自动做成可点index。需要走明确截图x/y坐标路径，或为safe_profile增加显式目标绑定的适配扩展，后者必须另列差异。[WIRE §Target，0x100079330、0x100079a88、0x100079ab4]

## ScreenCaptureKit shareable cache

ShareableContentCache为Swift actor，displayTTL30s、windowTTL2s；初始content=nil、fetchedAt=distantPast、inFlight=nil、lastSuccess=distantPast。fresh(maxAge)若content存在且age严格小于maxAge则返回；已有inFlight则await同task；否则创建SCShareableContent.getShareableContentWithCompletionHandler任务并保存。成功更新content/fetchedAt/lastSuccess、清inFlight；创建者失败invalidate content/time、清inFlight并归一化scDenied。已有joiner的unwind路径可能保留原错误，不宜统一猜成scDenied。[0x10003db50、0x10003df74、0x10003e27c、0x10003e430]

window(id)先fresh(2s)，按windowID找第一个；没找到invalidate，再fresh(2s)并找一次，仍无则nil。invalidate只清content和fetchedAt，不取消/清inFlight，也不重置lastSuccess。动态取消与并发错误身份须验证。[0x10003ec64、0x10003ee68、0x10003ee8c]

## SerializedElement 完整输出字段

始终输出6个key：ref:String、role:String、enabled:Bool、focused:Bool、actions:[String]、children_count:Int。可选存在才输出：subrole:String、role_description:String、title:String、value:String、description:String、selected:Bool、bounds:{x:Double,y:Double,w:Double,h:Double}；缺省不写null。children_count为原始AX children数，不是过滤后数量。[0x100011338–0x10001184c]

输出没有identifier、parent ref、嵌套children、depth或parentRoles。identifier/parentRoles是descriptor恢复内部数据。状态是扁平preorder列表。不要为了让模型方便而默默添加树结构并声称兼容；独立扩展必须另标schema版本。


## AX window 枚举与属性取值细则

AXBridge.windows按AXWindows原序遍历，不排序；copyAttr错误传播，nil或类型不对为空数组。另读AXFocusedWindow并CFEqual标focused。title缺省空串；position/size各自缺失用0,0；minimized缺省false；_AXUIElementGetWindow的输出先设0且忽略返回码，因此window ID0可保留。缺geometry不滤掉window。focused-first/first因此指AX原序，不能擅自改成CG z-order。[SNAP §10，0x1000109e4]

walk字段读取：role缺省空串；subrole/role_description可省；title取第一条非空String，优先AXTitle，其次AXTitleUIElement的AXValue，最后AXLabelValue。AXTitleUIElement强转可能trap，新实现防御须标偏离。value优先AXValue String，非String再NSNumber.stringValue；空String有效。description优先AXDescription String，即使空也不fallback；没String才AXHelp。enabled缺省true；focusedfalse；selected省略。bounds只有AXPosition与AXSize都成功才存在。descriptor内部保存祖先最后8个role，恢复比对最多最后3个；JSON不输出这两者。[SNAP §11]

## 两种 PID 解析必须分别实现

resolveActionPid不同于resolveApp：args.int(pid)经Int32checked转换后，只要正数就直接返回，不检查NSRunningApplication存活，也不比bundle。非正/缺失才用bundle，经resolveApp找运行app，失败可launchWithFrontmostPreserved，再返PID；最后nil由caller决定错误/reffallback。不存在一个可替代所有command的统一resolve函数。[WIRE末节，0x1000871b0]

|---|---|---|
| 原生windows/snap/get_app_state/raise | resolveApp有效PID优先，次bundle ID，再精确localizedName | 无目标app_not_found，不隐式frontmost；window选择各command不同 |
| 原生坐标动作 | resolveActionPid正PID优先且不验存活，次bundle查找/launch | 后续可能投向陈旧PID；独立safe实现需存活/身份绑定 |
| 原生e ref动作 | ElementStore Entry.element与Entry.pid | 外层bundle/PID不覆盖ref所属app |
| 原生click v ref | resolveActionPid加visualRefs[pid][ref]与lastMapping[pid] | 缺目标invalid_arg，缺框element_not_found，缺mapping internal |
| 普通MCP click ref分支 | 只转ref/button/count/strategy/cursor | 提供bundle也被动作payload去掉；批准/补图仍可用该bundle |
| sky click index分支 | per-app index map转ref，动作只送ref/options | map只来自elements，不来自visual_regions；vref不自动可用 |
| 原生shot有window_id | 直接指定CG window ID | 不要求bundle/PID；无ID时选app第一个AXwindow，不是focused优先 |
| 原生shot_display | cache选择显式display，缺省first display | metadata cursor无ID时CGMainDisplayID，可能与first display不同 |
| Appshot frontmost/capture | 前台描述符或显式解析，按额外命令契约 | 禁止把其frontmost默认传播到其它动作 |
| 原生PIP open/arm | 指定ID/PID或app窗口选择，详附录 | arm direct-ID需pid；title未中fallback focused/first |

各入口要保留自己的参数缺省与转发策略，safe_profile用显式扩展统一目标，不能偷偷篡改alma_0_4_164模式。


## 应用清单与使用历史

apps与list_apps不能互换。apps只取NSWorkspace中activationPolicy regular的GUI应用，name缺失用(unknown)，按初始采样的frontmost PID标active，name lowercased排序。list_apps把运行应用和Spotlight历史合并。

list_apps原生days缺省14、不限正负或最大值；MCP另有int最大90，<=0回退14。sky_list_apps传空args用native14。历史来源为NSMetadataQuery LocalComputerScope，不是Screen Time、Alma数据库或扫描所有文件。predicate要求content type精确等于com.apple.application-bundle且lastUsedDate>=now−86400×days；查询按lastUsedDate降序，2s超时丢弃history并返回running-only成功结果。完整query/runloop停止和update冻结见附录AppUsage契约。

运行seed只含regular app。按非nil bundle建dict，重复bundle后出现运行实例覆盖前一个；nil bundle另存array，不合并。初始useCount/date=nil，path=bundleURL.path，running=true，active按最初frontmost。history按query顺序合并：相同bundle保留运行row的name/pid/active/running；已有path非nil则保留（空串也算存在）；无path才用history.path。use_count和last_used_at每条history无条件覆盖，包括nil。无匹配bundle新建not-running row；nilbundle始终追加。

关键重复行为：history按最新先，但同bundle后到的更旧条目会覆盖count/date；非运行row的name/path来自最初那条。count不求和、不取max，date不保证最新；不能用常见“最新覆盖”算法替换原行为。

最终组合dict.values加nilbundle数组，稳定排序：active优先；再running优先；再use_count降序（nil当−1）；最后name.lowercased按Swift字符串升序。last_used_at不是最终排序key。完全同key保留输入序，dict枚举序本身不承诺固定插入顺序。[APP_USAGE_CONTRACT §3–6]

native row固定9key：bundle:String|null、name:String、pid:Int32|null、active:Bool、running:Bool、path:String|null、use_count:Int|null、last_used_at:ISO8601 String|null、intents:Array。日期用NSISO8601DateFormatter默认配置，不是Unix秒。intent只发name/description/required_params/optional_params，不发URL builder。普通MCP返回完整{apps}，sky返回转换array并省略null date/count和全部intents。

复刻顺序固定：running seed→受限时间history query→bundle-only merge→拼nilbundle→四级stable sort→九字段序列化→各包装转换。query超时、两个运行实例、重复history和nilbundle重复必须用合成输入验证。

## 原生禁止目标策略

ForbiddenTargets是另一层静态精确bundle集合，不能替代host批准或TCC。isForbidden(nil)=false；其余按Swift Set精确大小写匹配18项，不lowercase、不prefix/wildcard、不查code signing/team/executable path、不按类别推断。完整18项及VA在forbidden-bundle-constants.json与附录；例如SecurityAgent大小写敏感，dock.extra不等于dock。[FORBIDDEN_TARGETS_CONTRACT]

PID gate：allowOverride为true即返回；PID缺失、NSRunningApplication不存在、bundle缺失或不在集合也返回；命中抛forbidden_target。bundle gate不查进程，直接精确集合命中即拒绝。较长hint在本手册等义概述：它提示存在force_forbidden显式覆盖；不承诺hint完整字节，更不构成任何助手/部署可越过权限或确认政策的授权。

只有9个PID-gated cmd：click、perform_secondary_action、drag、type、type_text、press、press_key、scroll、set_value；另intent/open_url走bundle gate。select_text、launch_app、raise、remote_input和观察/管理命令不在该dispatcher集合。preflight仅resolveActionPid(args)，不会先读e-ref owner。因此ref-only动作可通过nilPID gate，随后实际操作Entry.pid；传错PID也可能批准与动作不同目标。这是已证覆盖差异，不是TCC被绕过。

force_forbidden经bool helper，Bool true或非零Int为true，字符串true不算；缺省false。MCP公开schema未因此自动新增该参数。独立safe_profile应以最终ResolvedTarget绑定gate并把该override能力保持关闭，任何真正需要系统隐私交互的场景仍走相应用户授权与OS保护。
