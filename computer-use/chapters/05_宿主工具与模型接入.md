# 宿主工具与模型接入

## 两条入口不能混成一个调用链

模型路径为：模型选择 computer-use__工具 → 通用工具包装 Qk → MCP manager → stdio MCP进程 → helper socket → native。MCP进程拥有Computer Use的schema、部分应用批准检查和截图返回约定。

本地路径为：CLI或UI → 127.0.0.1 HTTP /api/computer-use/... → 宿主单例helper client → 同一个helper socket。直接REST动作不经过stdio MCP，已检查handler中没有调用应用批准ledger。Appshot和PiP也是宿主helper client的消费者，不能把它们与模型get_app_state合成同一个“截图功能”。[HOST §1、§5；evidence.json原始定位]

本地服务监听127.0.0.1。已检查共同middleware包括CORS、活动/metrics、50MB JSON和urlencoded解析、gallery静态文件与日志；未见该共同链设置全局bearer token或逐app批准。该事实只描述本地信任边界，不证明远程可达、可利用性或绕过TCC。[HOST §1]

## 自动注册与工具发现

非headless正常启动在MCP初始化之前导入Computer Use注册模块；非macOS直接返回。读取 ~/.config/alma/mcp.json，按Resources/cli、Resources/bin、app.asar.unpacked/bin、开发祖先目录和app路径找MCP入口。打包版用Electron executable加ELECTRON_RUN_AS_NODE=1；开发版用node。配置key为computer-use。缺失时新增；识别为旧Alma入口时更新路径/命令；自定义入口args不指向Alma脚本时保留。解析配置失败会告警并在内存重建，成功注册写入可替换原文件。启动注册不是TCC授权。[HOST §2]

MCP manager创建stdio transport；connect race为60s，listTools为15s，可选resources/templates各15s。发现后使用server__tool命名，保存schema、description、_meta。输出安全模式metadata会影响通用压缩。初始化成功不代表每轮模型都能看到该工具。

## 五种控制边界

1. 每轮工具选择：no-tools或图像生成模型分支可移除工具；显式选择、自动选择、历史选择与tool search决定activeTools。启用MCP服务器的工具才进入自动候选；ACP有独立适配路径
2. 项目能力边界：非空restricted.mcpServers按工具名双下划线前缀过滤；空列表不限制；builtin限制另算。它是能力筛选，不是文件系统/native sandbox
3. 插件hook：tool.willExecute可取消或改args，成功hook可改result。存在hook机制不等于当前已装批准hook
4. 产品应用ledger：已有批准且未撤销则允许并累加用量。strict approval缺省或不严格等于true时，新app/撤销app可自动批准。严格模式才返回拒绝；该HTTP检查本身不弹确认框
5. macOS TCC：AX与屏幕录制权限独立，由helper和OS处理。可用helper路径、ledger允许、MCP工具可见都不代表OS授予权限

因此，MCP包装遇批准服务错误fail-open，不足以推出整个产品没有授权；另一方面也不能把项目筛选当成直接REST的逐app授权。[HOST §3；AUDIT 4]

Ledger记录bundle ID、app name、批准/撤销时间、使用次数与最后使用时间。动作日志只有setting严格为true时启用；保存tool、bundle、PID、args、duration、截图hash、error code；args为JSON，已检查写入路径未见脱敏。保留策略删除除最新N行以外的数据。新实现的日志应明确text等敏感输入是否保留，不能凭“本地”认定无隐私风险。

## helper client 状态机

helper定位先Resources/Alma Computer Use.app/Contents/MacOS/AlmaComputerUse，再开发fallback。isAvailable只证明macOS及文件存在，不证明握手、权限或事件成功。socket位于Electron userData，未ready时回退用户Application Support/Alma；后缀是helper路径字符串SHA1前8位，不是二进制hash。

- disconnected收到call：平台不支持则拒绝，否则connecting
- connecting先连已有socket；成功后ready
- 首次连接失败：spawn daemon --socket PATH --idle-seconds 900
- 每100ms重试，约4s后仍失败则helper-unreachable；同时发起的connect共享promise
- ready调用：生成8随机字节hex id，注册pending及timer，发送{id,cmd,args}+LF
- 响应：按id匹配并resolve/reject；未知id忽略
- timeout：本地移除pending和reject；不向native发送cancel
- close：拒绝所有pending为helper-disconnected，通知disconnect listeners；检查分支未显式清空半行buffer
- shutdown：尽力调用shutdown（2s），destroy socket、拒绝pending、SIGTERM自己追踪的child；已连接daemon未必是该host所spawn
- 应用退出前：异步启动shutdown

普通command20s；get_app_state、shot、shot_display、Appshot capture30s。child不detached；转发stderr。child exit仅清child引用，不能代替socket pending清理。[HOST §4，原始offset：532978、533615、536295、536825、537721]

分帧容忍任意read分片、合包，坏JSON行忽略。宿主先用字面子串"evt":true判定事件fast path，再解析appshot.monitor/appshot.update；语义等价但空格不同的JSON可能没进入该fast path。监听器异常隔离。没有可见的connection epoch，残余半行在重连后影响首帧是需要fixture确认的静态风险。

## HTTP 命令与错误

宿主client可转发ping、permissions、grant、apps/list_apps、launch_app、windows、snap、get_app_state、click、perform_secondary_action、drag、type/type_text、press/press_key、select_text、set_value、scroll、lens、raise、shot、remote_input、shot_display、Appshot monitor start/stop/frontmost/capture、shutdown。它比23个公开MCP工具面更宽，不代表每个helper命令都有同名公开HTTP route。

已检查REST默认：body缺失为空对象；text缺省空字符串；replace、show_cursor缺省true；scroll pages缺省1；launch的activates只有严格true才为true。已知client/permission/stale-ref error映射HTTP400，其余helper error为500，保留code/message/hint。

PiP活动middleware只覆盖列出的部分command，而且launch_app route注册在该middleware之前并已结束response。因此不能按middleware名字列表直接断言REST launch_app一定触发镜像。它是fire-and-forget活动通知，不是动作成功屏障。[HOST §5]

## 四种时钟与停止语义

宿主通用watchdog通常300s；long/background分支14400s；显式正timeout加15s宽限并封顶1800s，另有环境override。MCP manager callTool为600s；helper普通20s/抓图30s；连接spawn retry约4s。批准fetch等无显式超时分支仍需独立测试。

Qk创建child AbortController并在watchdog触发时abort，然后race返回超时文本。但MCP execute只接args，没有把第二context/AbortSignal传入manager。原文本声称termination，不构成native实际停止证据。

stopGeneration停止模型生成、清thread状态、把in-flight工具part标output-error，并对追踪的Bash child先SIGTERM、3s后SIGKILL。检查到的MCP transport/helper client不在该Bash集合；该函数没有stopServer、stopAll、helper shutdown或native cancel。MCP transport关闭出现在server/app teardown或显式refresh/stop，不是普通停止生成。[HOST §6；AUDIT 1–3]

复刻时分开记录：用户请求停止、host UI已停止、MCP响应被抑制、socket断开、native事件结束。后者未被观测时结果为unknown，不自动重试，也不以UI状态反推系统已静止。

## 模型内容转换与错误损失

MCP text转模型text；image/audio加MIME转inline file；text/blob embedded resource转text/file；resource link转文本引用；未知block JSON字符串化；空content回退整个result JSON。只有host自己建立的exception sentinel被明确转error-text。

已resolve的MCP结果即使isError:true，adapter仍走普通content转换，且可触发成功didExecute处理。因此日志✓、HTTP成功、MCP调用完成都不等于动作成功。独立safe实现应保留isError、error code/hint、delivery状态，不要求模型读自然语言猜测失败。[HOST §7；AUDIT 9]

视觉guard在调用前按工具名/screenshot/i和Read图片扩展名判断，不是对所有返回图片的Computer Use工具作能力检查。get_app_state/click没被名字条件全面覆盖；adapter本身也不拒绝图片。另一个视觉fallback预处理扫描用户消息图片，不是所有tool result。最终provider是否接受、丢弃或报错须运行测试。

## 两种图片持久化路径

顶层image_base64路径：识别output-available tool/dynamic-tool的顶层image_base64（至少16字符）或image_cache_file；按实际字节hash取前16字符命名inline文件，MIME决定扩展；改写为cache filename，之后发模型前再水合。再水合要求basename，避免路径穿越；缺文件告警并保留现状。dataURL memo key是长度+首尾片段，并非完整hash；文件身份才使用真实字节hash。memo超过256项清空；gallery HTTP缓存一天。

MCP content图片路径：{content:[{type:image,data,mimeType}]}不匹配顶层image_base64外置识别。通用压缩保留image/audio/file二进制字段；存储sanitizer跳过tool-computer-use__前缀，也保留含MCP image content的对象。不能据顶层cache实现宣称所有MCP截图都已去重移出消息。

存储例外也不代表无限历史。normalization有10000000字符上限，后续context压缩仍可能改变保留范围。截图是否长期保留、token成本如何，必须沿真实provider路径验证。[HOST §7]

## Appshot preload 边界

同一helper socket同时承载请求响应和push事件；host分别维护monitor、context update、disconnect listener集合，各on方法返回unsubscribe。preload只暴露getState、setHotkey、captureNow、prewarm和四类订阅；已检查区域没有一个可任意传cmd的通用preload原语。生命周期细节见下一章；中文逐模块实施配方也完整保留在证据包的analysis/host目录。[HOST §8]


## 保存完整不代表模型看到完整

Computer Use存储例外不豁免Qk的模型结果压缩。含双下划线的通用MCP工具默认compact，除非_meta的alma/outputSafetyMode或description marker覆盖。已检样本业务区未发现该override字面量。MCP compact的序列化目标为2600字符，默认单string上限1000，继承text字段专用上限600；长文本归档并替换为首尾摘录和检索提示。超目标时缩小文本预算，但图片binary保护不截断，因此2600是目标而非含图片的硬上限。可能出现图片完整、AX文本严重缩短。

该处理发生在toModelOutput前。rawToolResults跳过压缩但不跳通用sanitize；/api/tools/invoke为PTC内部调用显式true。因此相同MCP结果经普通模型工具调用和PTC可能产生不同文本预算。验收必须比较完整AX文本、压缩文本、检索可用性和图片，不把落盘内容直接当模型输入。[HOST §10，pretty行25807–26053、26312–26332、79065–79079]
