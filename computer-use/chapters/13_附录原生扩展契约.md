### ping

Args none. Returns `{pong:true,version:"0.1.0",uptime_s:Int}`. uptime_s=Int(NSProcessInfo.processInfo.systemUptime), truncation toward zero; this is **OS uptime**, not elapsed daemon lifetime. Dispatch0x100076a24; version immediate0x100076a90–a98; clock0x100076ae0; cast0x100076b28. The helper protocol version0.1.0 is separate from app release0.4.164.

### permissions

Args none. Returns:

    {accessibility:Bool,screen_recording:Bool,
     focus_guard:{armed:Bool,arm_failures:Int}}

health tuple0x100076bcc; accessibility `isTrusted(prompt:false)`0x100076c38; screen capture permission probe0x100076c6c; nested health keys0x100076cb8–cf0. The SC permission probe uses ShareableContentCache via synchronous async bridge, so it is an actual permission check, not merely a stored preference. Missing permission is a false flag, not itself failure of this command.

### grant

Args none. Calls `isTrusted(prompt:true)`; returns `{prompted:true,accessibility:Bool}`. 0x100076d94–e18. `prompted:true` reports the requesting operation, not proof that permission was granted or UI appeared. Does not grant Screen Recording automatically.

### apps

Args none. Returns `{apps:[{bundle:String?,name:String,pid:Int32,active:Bool}]}`; mapper0x10007fa04 builds exactly four fields bundle/name/pid/active. RunningApps selection/sort policy is closed in the follow-on subsection below; do not substitute list_apps.

### windows

Args `bundle?:String,pid?:Int32` using args coercions; same resolveApp PID-first/live-app fallback defined in WIRE_SCHEMA. No implicit frontmost.

Returns `{app:{bundle:String?,pid:Int32},windows:[{id:UInt32,title:String,bounds:{x,y,w,h},minimized:Bool,focused:Bool}]}`. App object contains bundle and pid, not localized name in this branch. Native calls resolveApp0x1000770d0 then AXBridge.windows0x1000770f0; wraps app/windows at0x100077130–74e8. Window mapper0x10007ff34–8027c. Windows retain AX source order; no sorting. Missing app -> appNotFound; AXWindows copy errors propagate via CUError; nil/unconvertible AXWindows yields empty array. See FINDINGS section10 for focused/geometry/ID defaults.

### snap

Literal `snap`, not `snapshot`. Args bundle?,pid?,window_id?,depth=6,interactive_only=true,wakeup_seconds=0. Returns full SnapshotResult dictionary and does not run AppStateDiff or capture. Exact schema/algorithms in FINDINGS sections2–4. This is optional direct-native functionality; current wrapper post-action uses get_app_state and therefore has different diff effects.

### raise

Args `bundle?:String,pid?:Int32,window_id?:UInt32`; checked conversions can trap if out of range. Uses resolveApp then AXBridge.windows. Window selection: explicit matching ID first, else focused first, else first AX window. Calls AXRaise on chosen AX element (0x10001683c); return checked through AX error path; success data `{raised:true}` (0x10007dbc4–be0). It is not guaranteed to activate the application or preserve user focus; AXRaise runtime behavior depends on the app.

Important: empty AX window array reaches BRK in selection0x100016918 rather than a demonstrated friendly no-window error. Hardened replica should return typed error, declaring this difference. Native symbol entry0x100016670; dispatcher0x10007db80.

### shot

Args:

- `out:String` required path; missing/empty/wrong type uses requireStr invalid_arg
- `max_width?:Int`, no native default (nil means no cap)
- `window_id?:UInt32`
- `bundle?:String,pid?:Int32`, used only when window_id absent

Algorithm: if window_id supplied, capture it directly without requiring PID/bundle; otherwise resolveApp and choose **first AX window**, not focused preference. If array empty, internal error message `App has no windows to capture.` (0x10007e810–830). Calls Capture.captureWindow ScreenCaptureKit via runAsync0x10007e508, quality fixed0.85. Failure propagates native failure; no AX-success/screenshot_error wrapper unlike get_app_state.

Result `{path:String,width:Int,height:Int,cursor?:{x:Double,y:Double}}`. Capture image always writes supplied path. Optional cursor is normalized0..1 logical ActionCursor position within **live CG window bounds**; omit when window bounds absent, no current ActionCursor, nonpositive rect size, or cursor outside rect. It is metadata, not a burned-in cursor. Base fields0x10007e8cc–91c; windowBounds0x10007e93c; ActionCursor.normalized0x10007e95c; cursor insertion0x10007e9fc. Successful shot does **not** update Daemon.lastMapping or visualRefs in this dispatch path. Those caches belong to get_app_state screenshot flow.

### shot_display

### 1. Entry points and days

- Public MCP `list_apps`: source lines 36007–36024. Input `days` is optional Zod number, integer, maximum 90, with **no schema minimum**. The handler sends `{days: posIntOr(args.days,14)}`; `posIntOr` requires a finite numeric value greater than zero, then floors it, otherwise returns 14. Consequently valid MCP positive values are integers 1–90, while zero and negative integers are accepted by the schema but become 14. Missing becomes 14; fractions and values above 90 fail schema validation rather than being clamped. No interaction gate wraps this tool. The result is one text content block containing `JSON.stringify(res,null,2)`.
- Native dispatcher branch `0x100076f8c–0x100077004`: reads `days` using the native optional-dictionary `int` accessor at `0x100076fa4`; missing/null value or an accessor parse failure gets literal 14 via `mov w8,#0xe` / `csel x0,x8,x0,eq` at `0x100076fb0–fb4`; calls `AppUsage.listApps(days:)` at `0x100076fb8`.
- Swift default-argument generator `0x10003791c`: `mov w0,#0xe; ret`.
- The native `int` accessor also accepts Double (truncate toward zero) and signed decimal String, after trying Int (`0x100006308–6340`, `0x100006388–6400`, `0x100006404–66bc`; see `WIRE_SCHEMA.md`). Non-finite/out-of-Int-range Double conversion traps at `0x1000066c8–66d0`; that is not the default14 fallback. Ordinary MCP schema validation excludes these non-integer/non-number inputs before native forwarding.
- Native AppUsage has **no positivity or maximum clamp**. It passes the original integer to `recentMetadata` at `0x1000384e8–4f0`. `recentMetadata` holds the argument in x20 from `0x10003b720`; at `0x10003b994–9b8` it constructs Date(), converts x20 with `scvtf d0,x20`, multiplies by IEEE754 bits `0xc0f5180000000000` (= -86400.0), and calls `Date.addingTimeInterval`. Native direct callers can therefore request zero, negative, and >90 windows. Do not incorrectly impose the MCP restriction on the raw daemon contract.
- Public `sky_list_apps`, lines 36294–36310, sends native `list_apps` with `{}`, so native default 14 applies. It returns a JSON text **array** transformed from `res.apps ?? []`: `id = a.bundle || a.name || "unknown"`, `displayName = a.name`, `isRunning = a.running ?? a.active`, `lastUsedDate = a.last_used_at ?? undefined`, `useCount = a.use_count ?? undefined`. Missing/null lastUsedDate/useCount are omitted by JSON.stringify. This differs from the ordinary tool's full native result object.

### 2. Native result shape

Native result is `{apps: [row, ...]}`. Dispatcher builds the `apps` dictionary, with the mapped array at `0x100076ff0–0x100077000` and shared dictionary-return tail `0x100076ec4–0x100076f18`. Each row has **nine** keys, built by mapper `0x100080884–0x1000810a8`:

| JSON key | Type / value | Primary instruction proof |
|---|---|---|
| bundle | String or null | Small-string literal at `0x100080978–994`; AppInfo+0 and +8 read at `0x100080924`; optional nil branch `0x1000809ac–9b8` |
| name | String | Literal `0x1000809bc–9d0`; AppInfo+0x10/+0x18 stored `0x1000809d4–9d8` |
| pid | Int32 promoted to signed integer, or null | Literal `0x1000809dc–9f4`; optional tag at +0x24; `ldrsw` from +0x20 at `0x100080a14` |
| active | Bool | Literal `0x100080a24–a38`; value from AppInfo+0x25 at `0x100080a3c–a48` |
| running | Bool | Literal `0x100080a4c–a64`; value from AppInfo+0x26 at `0x100080a68–a6c` |
| path | String or null | Literal `0x100080a70–a80`; AppInfo+0x28/+0x30, optional test `0x100080a84–ab0` |
| use_count | Swift Int or null | Literal `0x100080ab4–ad0`; value +0x38, optional tag +0x40 at `0x100080ad4–afc` |
| last_used_at | ISO8601 String or null | Literal `0x100080b00–b20`; optional Date copied/tested `0x100080b24–b64`; nil existential is zeroed `0x100080b68–b6c`; nonnil formatting `0x100080ba0–c28` |
| intents | Array of objects, possibly [] | Literal `0x100080c3c–c50`; exact bundle lookup `0x100080930–940`; nil bundle gets empty array at `0x100080948`; empty registry array branch `0x10008101c–1028`; emitted array stored `0x100081040–1048` |

The mapper destroys exactly nine key/value literal entries at `0x10008107c` (`mov w1,#9`) after building `[String:Any?]` at `0x100081050`. Optional fields remain present as null in the canonical native JSON conversion; they are not all omitted like the sky adapter's optional date/count fields.

`last_used_at` uses a newly initialized `NSISO8601DateFormatter` for each present date, then `stringFromDate:`; no formatter options, timezone, fractional-seconds option, or custom format is configured in the mapper. This is Foundation's default ISO8601 formatter behavior. Classref `0x1000ae488` contains raw chained-bind word `0x80100000000002c9`; fixups import index 0x2c9 resolves `_OBJC_CLASS_$_NSISO8601DateFormatter`. Do not substitute Unix epoch numbers or a locale-dependent date formatter.

Each intent has precisely `name:String`, `description:String`, `required_params:[String]`, `optional_params:[String]`; key/value materialization `0x100080cb0–0x100080d50`, dictionary capacity four at `0x100080d54`, array append `0x100080fd4–fe8`. No URL/build closure is emitted. Registry order is preserved by this map. Exact entries are in the companion document.

### 3. Running-app seed

1. Start a `[String:AppInfo]` dictionary and a separate array for rows without bundle IDs (`0x100037cb4–cc4`, `0x100037de4–dec`).
2. Read `NSWorkspace.shared.frontmostApplication`; capture its PID if present (`0x100037ccc–0x100037d30`). Retain a separate presence test, so absence does not make PID 0 active.
3. Read `NSWorkspace.shared.runningApplications` (`0x100037d34–d80`) and enumerate its order (`0x100037e18–e58`).
4. **Include only activationPolicy == 0 (`.regular`)**. Call and `cbnz` skip are `0x100037e5c–e64`. Accessory/prohibited/background apps are excluded from the running seed; the metadata stage is not filtered by activation policy.
5. For each included application:
   - `bundleId = bundleIdentifier` optional (`0x100037e68–ea0`)
   - `name = localizedName ?? "(unknown)"` (`0x100037eac–ef0`); the fallback is the exact lower-case, parenthesized string decoded from immediates 0x6e776f6e6b6e7528 + 0xe900000000000029
   - `pid = processIdentifier` (`0x100037ef8–efc`)
   - `active = frontmost exists && processIdentifier == frontmostPID` (`0x100037f04–f24`)
   - `running = true` (`0x100038068–06c`)
   - `path = bundleURL?.path`, not executableURL (`0x100037f30`, `0x100037ff4`); no URL -> nil (`0x100037fd0–fec`)
   - `useCount = nil`, `lastUsedAt = nil` (`0x10003801c–03c`, `0x100038074–078`)
6. Non-nil bundle IDs are dictionary keys with normal exact Swift String equality. A later running application with the same bundle replaces the entire earlier AppInfo (`find` `0x1000382a8`; found branch `0x100038388–3a4`; insertion `0x1000383d0–444`). No PID/path disambiguation and no explicit case folding are used.
7. Nil bundle rows append separately (`0x1000381e4–264`). They are not deduplicated by name, path, or PID.

### 4. Spotlight history source and query lifecycle

`AppUsage.recentMetadata(days:)` is `0x10003b6fc–0x10003c750`. The source is **NSMetadataQuery**, not Screen Time, an Alma-maintained database, launch logs, recent-document menus, or a recursive filesystem scan.

#### Configuration

- Allocate/init NSMetadataQuery at `0x10003b8f4–b904`. Classref `0x1000ae508` raw bind word `0x80100000000002d9`, fixups import 0x2d9 = `_OBJC_CLASS_$_NSMetadataQuery`.
- Set search scopes to a one-element array containing **NSMetadataQueryLocalComputerScope** (`0x10003b940–988`). GOT slot `0x1000a4800` resolves that exact symbol using LC_DYSYMTAB indirect symbols; raw bind word `0x80100000000000f8`.
- Cutoff: current Date plus `-86400.0 * Double(days)` as above. The comparison is inclusive.
- Predicate format at raw C-string VA `0x100093240`: `kMDItemContentType == 'com.apple.application-bundle' AND kMDItemLastUsedDate >= %@`. Construct NSPredicate with the cutoff NSDate at `0x10003b9fc–ba9c`. Equality on content type is exact; this is not a ContentTypeTree/conformance test.
- `valueListAttributes` = `["kMDItemDisplayName", "kMDItemCFBundleIdentifier", "kMDItemLastUsedDate", "kMDItemUseCount", "kMDItemPath"]`. Static Swift array begins VA `0x1000b0730`, count 5 at +0x10, capacity word 10 at +0x18, elements at +0x20. Its large strings point to C-string VAs `0x1000932a0`, `0x1000932c0`, `0x1000932e0`; the last two are inline Swift small strings at `0x1000b0780`, `0x1000b0790`. - Query sort descriptor is `NSSortDescriptor(key:"kMDItemLastUsedDate",ascending:false)` (`0x10003bb38–bb60`; w3=0); installed at `0x10003bba8`. Thus metadata is traversed in descending last-used order before the independent final AppInfo sort.

#### Execution and fallback

- Create semaphore value 0 at `0x10003bbb4–bbb8`.
- Add default NotificationCenter observer for **NSMetadataQueryDidFinishGatheringNotification**, scoped to this query object, with queue nil (`0x10003bbe4–bbec`, `0x10003bc74–bc88`). Exact notification GOT slot `0x1000a47f8` resolves the named symbol, raw bind word `0x80100000000000f7`.
- Observer closure `0x10003da34–da50` only signals the semaphore (`0x10003da44`).
- Dispatch `startQuery` asynchronously to the main queue (`0x10003bce4`, `0x10003bde8`); closure `0x10003da70–da74` tail-calls `startQuery`. The Bool return of startQuery is not used to produce an error.
- Wait until `DispatchTime.now() + 2.0` (`0x10003be44–be58`, literal `fmov d0,#2`), semaphore wait `0x10003be80`; compare return against timeout (`0x10003be94–bea0`).
- Enqueue `stopQuery` asynchronously on main queue in either case (`0x10003beac`, `0x10003bf78`; closure `0x10003db0c–db10`). Then remove the observer (`0x10003bfd4`). There is no `disableUpdates` call and no synchronous main-queue stop before result extraction.

- On successful gathering, read `resultCount` and iterate `resultAtIndex:` (`0x10003c018–c028`, `0x10003c110–c160`). Rows failing the conditional NSMetadataItem cast are skipped. Zero results returns [].

### 5. Exact merge and duplicate behavior

After collecting running apps, call recentMetadata once (`0x1000384e8–4f0`) and traverse its rows in returned order (`0x100038508–5e8`). For each metadata entry `m`:

- If m.bundleId exists and currently matches a dictionary row:
  - Preserve that row's bundle, name, pid, active, running (`0x10003866c–6a4` saves fields; `0x10003871c–754` restores them)
  - Preserve its path **if non-nil**; otherwise use m.path (`0x1000386a8–6e0`; `cbnz x26` skips fallback). Empty path counts as non-nil and is not subsequently improved
  - Replace useCount and lastUsedAt with m's optional values **unconditionally**, including nil (`0x1000386e4–718`, `0x100038758–760`)
  - Write the updated row back to the dictionary under that bundle (`0x100038c64–d80`)
- Otherwise make an AppInfo from metadata: bundle/name/path/useCount/date from m, pid=nil, active=false, running=false (`0x1000388ac–914`, notably `strh w8,[x24,#0x24]` with w8=1 encodes optional PID nil plus active false, and `strb wzr,[x24,#0x26]` running false)
  - With a non-nil bundle, insert it into the same dictionary (`0x10003891c–920`, `0x100038b04–c5c`)
  - With nil bundle, append to the separate unbundled-row array (`0x100038a68–afc`)

Important reproducibility edge cases:

1. Matching is **bundle-only**. There is no path/name matching for an unbundled app. A running unbundled row and metadata unbundled row for the same application remain two entries.
2. All bundled metadata rows deduplicate into the dictionary, even if none was originally running. Multiple installations with the same bundle ID become one row.
3. For duplicate metadata bundle IDs, the **first/newest** metadata row provides the name/path of a non-running row, but **each later/older row overwrites count/date**. Since query order is lastUsed descending, the last matching metadata row determines final use_count and last_used_at. Counts are not summed, maximized, or tied to the retained path. No newest-wins test appears in the merge path.
4. A previously running row's name/PID/flags remain the running row's values, even when a newer history entry exists. Dictionary replacement among running instances occurs before history merging, so the last running instance enumerated supplies them.
5. Unbundled rows are never deduplicated, neither running vs history nor metadata vs metadata.

Before final sort, form `Array(dictionary.values)` (`0x100038eb4–f18`, including concrete Dictionary.Values copy helper at `0x100038ef4`), then append the unbundled array (`0x100038f20–f30`). Therefore a fully tied pair of bundled rows has dictionary-enumeration order, not a promised deterministic insertion order. Unbundled rows enter after all dictionary rows, with their original running-then-metadata traversal order.

### 6. Final sort comparator, fully closed

`0x100038f4c` calls specialized sort `0x100039140`. It chooses insertion sort for short runs (`0x1000391dc–1ec`) and `_stableSortImpl` for larger arrays (`0x100039220–224`). The clearest inlined comparator is in insertion sort `0x100039dc0–e88`:

```
if lhs.active != rhs.active: return lhs.active
if lhs.running != rhs.running: return lhs.running
let l = lhs.useCount ?? -1
let r = rhs.useCount ?? -1
if l != r: return l > r
return lhs.name.lowercased() < rhs.name.lowercased()
```

Proof:
- active byte +0x25 comparison `0x100039dc0–dcc`; unequal branches with lhs flag in w22
- running byte +0x26 comparison `0x100039dd0–ddc`; same behavior
- lhs optional count tag +0x40 and count +0x38 at `0x100039de0–dec`; `csinv x8,x8,xzr,ne` produces -1 when nil; rhs analogous `0x100039df0–e14`
- descending signed count: `cmp x9,x8; cset w22,lt` at `0x100039e84–e88`
- lowercasing both names `0x100039e18–e2c`, strict Swift string-less comparison (`w4=1`) `0x100039e50–e60`
- equality returns no swap (`0x100039e3c–e4c` to `0x100039d48`), preserving stable input order for equal keys

**last_used_at is not used by the final comparator.** It filters/sorts the Spotlight input only. There is no bundle, PID, path, or raw-case name secondary tiebreaker. A negative count below -1 can sort behind a nil count because nil is explicitly -1, not a separate missing-value class. Replicas should reproduce Swift lowercased/string comparison semantics rather than locale-aware display-name sorting.

### Shared input interpretation

All argument keys below live inside `args`.

- `str(key)` at `0x100006140`: String cast only; absent/null/wrong type gives nil. Empty String remains present.

### 1. `pip_open`

Entry `0x10007c42c`; resolver `0x100088f74`; manager `0x1000485e0`.

| Key | Parser | Default / role |
|---|---|---|
| `window_id` | int then checked UInt32 | nil; selects direct-ID path if present |
| `pid` | int then checked Int32 | nil; optional metadata on direct-ID path, otherwise app selector |
| `bundle` | str | nil; read only on no-window_id app-resolution path |

#### Window resolution

Equivalent branch logic:

    if window_id parses:
        checked UInt32(window_id)
        pid = optional checked Int32(args.int("pid"))
        resolved = (window_id, pid, args.str("title") ?? "")
        // No resolveApp call and no ownership cross-check here.
        // bundle is ignored.
    else:
        app = resolveApp(bundle: args.str("bundle"),
                         pid: optional checked Int32(args.int("pid")))
        windows = (try? AXBridge.windows(app)) ?? []
        if windows.empty:
            throw internal("App has no windows to mirror.")
        selected = selectWindow(windows, args.str("title"))
        resolved = (selected.id, app.processIdentifier, selected.title)

`selectWindow`, in enumeration order:

1. If requested title is nonempty, return the first exact title equality match
2. Otherwise, still for a nonempty requested title, return the first whose title `contains(requestedTitle)` using Swift/Foundation String.contains without case-folding options
3. If title is absent/empty **or neither title match exists**, choose first `focused == true`
4. Else choose first window

A mismatching title is a preference, not an error. The fallback flag is definitely **focused**, not minimized or main: WindowInfo getter `0x1000109bc` reads byte +0x41; this is the flag tested at `0x100089244–248`. No minimized filter is present in this selection.

`resolveApp` is the shared AXBridge helper (`0x10001024c` wrapper, actual `0x100019718`): live explicit PID first; if unavailable, `bundle` exact bundle ID first match; if none, exact localized application name first match. With neither usable selector, error label is `pid=0`, not a frontmost-app default. See `WIRE_SCHEMA.md` for its app-not-found error.

Resolution evidence: direct-ID path `0x100088fa4–0x100089060`; app path `0x100089080–0x1000890d4`; exact/contains `0x1000890dc–0x10008921c`; focused/first `0x100089220–0x100089298`; no-windows error `0x10008929c–0x1000892fc`. AX window enumeration errors are caught and replaced with an empty array at `0x1000890b8–0x1000890cc`, thereby losing the underlying AX error.

#### Preferred size and title

Only if width **and** height parse and each compares >0 is `CGSize(width,height)` passed as the preferred size. Otherwise the entire preferred size is nil; a valid one-dimensional value is not used by itself. This is silent defaulting, not invalid_arg. Width is tested at `0x10007c980–984`, height at `0x10007c98c–994`, with nil tagging `0x10007c694–6a0`/`0x10007c970–99c`. NaN fails these comparisons; positive infinity is not explicitly rejected by dispatch.

For a new session with nil preferred size (`0x10004ad14–0x10004ada4`):

    sourceW = max(SCWindow.frame.width, 1)
    sourceH = max(SCWindow.frame.height, 1)
    aspect = sourceW / sourceH
    width = min(max(sourceW / 3, 240), 960)
    height = width / aspect

A provided positive pair replaces both calculated dimensions without aspect-ratio normalization. Constructor also sets the floater minimum size to 200×150 at `0x10004aec0–0x10004aed8`; actual enforcement by AppKit is a runtime boundary. The returned frame is the actual native window frame, so do not claim it always equals the requested content size.

### 4. `pip_arm`

Entry `0x10007cbc8`; resolver `0x100089414`; armer `0x10004e480`.

#### Parsed arguments / resolution difference

Reads `window_id` via int→UInt32, `title` via str, `pid` via int→Int32, `bundle` via str. No width/height or size is read.

The direct path requires **both** parsed window_id and parsed pid:

    if window_id != nil and pid != nil:
        resolved = (window_id, pid, title ?? "")
    else:
        app = resolveApp(bundle, pid)
        windows = (try? AXBridge.windows(app)) ?? []
        if windows.empty:
            throw internal("App has no windows to arm.")
        selected = same selectWindow rules as pip_open
        resolved = (selected.id, app.processIdentifier, selected.title)

Consequently `pip_arm({window_id:123,bundle:"Example"})` without pid resolves Example and chooses a window; it does **not** guarantee arming window 123. With no pid/bundle, window_id alone reaches shared app resolution and fails. Conversely explicit window_id+pid avoids app-resolution liveness/ownership validation, then the armer checks that ID occurs in that PID's AX windows. Direct path `0x100089444–46c` then `0x1000896f0–71c`; no-ID/no-PID path starts `0x100089470`.

Selection is exact title, contains title, focused, first; no title match error. Empty title becomes nil when passed to the armer (`0x10007cd58–0x10007cf10`); armer stores nil as empty String.

#### Response

    {"armed":{"window_id":123,"pid":456,"title":"Window title"}}

The inner title is the resolved String, including `""`. `armed` is an object, not a Boolean or an array. Construction `0x10007d05c–0x10007d14c` then shared dictionary assembly `0x10007bd44–0x10007bd8c`.

Arming an already armed window ID is a no-op success: armer returns after its locked lookup (`0x10004e4e4–0x10004e524`). It does not update stored PID/title or replace observers. Dispatch still replies using this call's resolved tuple. Therefore a duplicate arm's response metadata can differ from later pip_status.armed metadata; status reports the original registration.

For a fresh entry, armer reads AXWindows for the supplied PID, finds first AX element whose `_AXUIElementGetWindow` ID equals window_id, creates AXObserver, adds AXWindowMiniaturized and AXUIElementDestroyed notifications, adds its source to main run loop, then stores (pid, element, title, observer). `_AXUIElementGetWindow`'s return code is not checked; output starts at zero. A zero ID can therefore behave unusually, rather than being explicitly rejected.

#### Errors and success caveat

- Shared app-resolution error
- `internal`: `App has no windows to arm.` (AX enumeration errors swallowed by resolver)
- `internal`: `No AX window element for windowId=<UInt32> pid=<Int32>` if AXWindows lookup fails, is absent, casts incorrectly, is empty, or has no matching ID. Producer `0x10004e580–0x10004e698`
- `internal`: `AXObserverCreate failed: <AXError integer>` when AXObserverCreate reports nonzero or returns no observer; producer `0x10004e9b0–0x10004ea6c`
- Checked-number traps as above

Both AXObserverAddNotification return codes are ignored (`0x10004e854`, `0x10004e890`). A successful armed response proves the code registered/stored an observer attempt, not that every application actually supports those notifications.

#### Minimize/destroy disposition (newly closed lifecycle detail)

Observer callback `0x100052754–0x100052c64` first requires nonnil context and a nonzero window ID obtained from the callback's element. Other notifications are ignored. Matching AXWindowMiniaturized queues the closure at `0x100052cd8`; AXUIElementDestroyed queues disarm at `0x100052c68`.

On queued minimize:

1. If PIPManager already contains that ID, disarm the entry and return (`0x100052d48–0x100052d7c`)
2. Else read armer's entry; if removed in the meantime, return (`0x100052db0–dd4`)
3. Open using stored ID/PID/nonempty title, no preferred size (`0x100052de4–0x100052e34`)
4. On successful open, release returned status and disarm (`0x100052fa0–0x100052fb4`)
5. On failed open, print `PIP auto-open on minimise failed for wid=<id>: <error>\n` to stderr and retain the armed entry (`0x100052e38–0x100052f9c`)

**Correction to a broader earlier lifecycle summary:** error does not auto-disarm here. The arming is one-shot on successful/existing open, but a failed attempt remains eligible for a later notification. The prior command response is not replaced by a later failure response.

### 2. `appshot_monitor_start`

Entry `0x10007ea8c`; main continuation `0x10007ef8c`.

#### Parameters and validation

| Key | Native parse | Default | Validation |
|---|---|---|---|
| `hotkey` | optional String | nil | If present and nonempty, must exactly match `DoubleCommand`, `DoubleOption`, or `DoubleShift` |

Missing, wrong-type, null, and empty hotkey are all mapped to optional-enum nil. There is no native default to DoubleCommand. Nonempty unknown/case-mismatched text throws `CUError.invalidArg` with the exact interpolated message:

`Unknown hotkey: <value>. Valid: DoubleCommand, DoubleOption, DoubleShift`

Evidence: parse `0x10007ea8c–0x10007ead8`, error assembly `0x10007eadc–0x10007eb70`, optional conversion `0x100082bd8–0x100082c24`, exact enum string switch `0x10006f2ac–0x10006f304`.

#### Subscription and shared monitor state

1. If a ConnectionContext exists, add a subscription to `appshot.monitor` unless that connection's token list already contains that exact topic
2. Likewise subscribe once to `appshot.update`
3. Tokens are stored as `(topic:String, token:UInt64)` in the connection
4. Callback weakly captures the connection and forwards serialized event lines through ConnectionContext.send(line:)
5. Regardless of whether a connection context exists, call global singleton `BareModifierMonitor.start(hotkey:)`

Subscriptions happen before starting the monitor and are not rolled back when its start result reports failure. Repeated start does not duplicate either topic subscription, but does reconfigure the global monitor, including when the caller changes the hotkey. Thus clients do not get independent per-connection hotkeys.

Evidence: monitor dedup `0x100082c28`, update dedup `0x100082cbc`; subscription/store `0x10007ef8c–0x10007f13c`; weak forwarding `0x100089a6c–0x100089ac0` (update thunk at `0x10008b06c` routes through the same implementation).

#### Result

```json
{"started":true,"hotkey":"DoubleCommand","supported":true,"error":null}
```

Fields are `started:Bool`, `hotkey:String?`, `supported:Bool`, `error:String?`. `hotkey` echoes the parsed requested enum, not a later read of actual tap state. Nil hotkey is represented as optional nil in the result dictionary.

- `supported` is a fresh `AXIsProcessTrusted()!=0` call (`0x10006db04`)
- `start` first checks `AXIsProcessTrusted`; failure returns `(false,"Accessibility permission not granted")`
- It ensures a monitor run-loop thread, with a semaphore wait bounded at 1 second; absent run-loop returns `(false,"Failed to start Appshots monitor thread")`
- If a run-loop exists it schedules `applyHotkeyOnMonitorThread`, wakes the loop and immediately returns `(true,nil)`
- Therefore `started:true` confirms scheduling, not successful CGEventTap creation
- With nil hotkey, the scheduled operation tears down the old tap, sets current hotkey to nil, and returns without installing a new tap or broadcasting ready

Evidence: result assembly `0x10007f174–0x10007f490` and `0x10007f700–0x10007f728`; start `0x10006db78–0x10006dcf0`; run-loop wait `0x10006dea4–0x10006dee0`; apply nil branch `0x10006df78–0x10006dfb8`.

#### Monitor event payloads

All of these use topic `appshot.monitor`:

```json
{"type":"ready","hotkey":"DoubleCommand"}
{"type":"error","message":"CGEvent.tapCreate returned nil — Accessibility not granted to Alma Computer Use, or a higher-priority tap claimed the slot"}
{"type":"down","hotkey":"DoubleCommand","frontmost":{}}
```

- Ready is broadcast after the tap is installed/enabled and current hotkey updated
- Tap failure is asynchronous: it can follow a successful `started:true` command response; the same diagnostic is also written to stderr with `[appshot-monitor] ` prefix
- Down includes `frontmost` only when `Appshot.frontmostWindow(excludeBundleId:"com.yetone.alma")` finds a candidate; absent candidate means the key is omitted, not an empty object
- The down event does not itself invoke `Appshot.capture`; it supplies context for the client to decide what to capture
- The native exclusion for hotkey-triggered lookup is hard-coded to `com.yetone.alma`

Evidence: tap creation/apply `0x10006dfbc–0x10006e47c`; down construction and frontmost attachment `0x10006f758–0x10006fa38`.

#### Low-level hotkey detection

Instruction-proven constraints, useful for compatibility tests:

- CGEventTapCreate is invoked with location 1, placement 0, options 1, event mask `0x1000` (`flagsChanged` event type 12)
- Handler ignores event types other than 12
- DoubleCommand checks device-dependent flag pair `(0x8,0x10)`; DoubleOption `(0x20,0x40)`; DoubleShift `(0x2,0x4)`
- It tracks the prior left/right bits; any bit from `0x7e` outside the selected pair clears the pending tap timestamp
- Both selected bits held can fire; a rising selected-side transition can also fire if the prior pending timestamp is at most 0.35 seconds old
- A last-fire timestamp enforces a 0.5-second cooldown; release during cooldown clears pending tap state
- An old pending timestamp is cleared once it exceeds 0.35 seconds

These points come from `0x10006e874–0x10006edc4`; exact host keyboard hardware behavior remains a runtime validation item. The named Double variants should not be simplified to generic keyDown events.

### 3. `appshot_monitor_stop`

Entry `0x10007ee2c`. No parsed parameters. Result:

```json

```

Important asymmetry:

1. With a ConnectionContext, filter its token list for the exact topic `appshot.monitor`
2. Unsubscribe those tokens and remove those same entries from the connection
3. Leave `appshot.update` tokens installed
4. Query the global subscriber count for `appshot.monitor`

#### Capture sequence and errors

1. Resolve an application using `AXBridge.resolveApp(bundle:pid:)`; normal resolver errors propagate
2. If explicit window_id is absent, choose `WindowList.topWindow(for:resolvedApp.pid)`
3. If that is absent, throw CUError.internalError with `Target app has no on-screen window to appshot`
4. Create out_dir with intermediate directories enabled; directory-creation error is caught/discarded, so a later image-write error can become the externally visible failure
5. Capture a timestamp `Date.timeIntervalSince1970`, multiply by 1000, truncate to Int, and form `appshot-<milliseconds>-<windowId>.jpg` with NSString.appendingPathComponent
6. Try synchronous `Capture.captureWindowFast(windowId:outputPath:maxWidth:)`
7. If fast capture returns nil, await `Capture.captureWindow(...)`; its thrown errors propagate
8. Look up matching WindowList entry for title/frame metadata when available, and encode the resolved application's icon
9. If `AXBridge.isTrusted(prompt:false)` is true, launch background AX work; do not wait for its text before constructing the response
10. Return capture result with empty axText

Explicit window_id is passed directly into the capture path after resolving the app; the shown dispatch/capture preamble does not validate that this window belongs to the resolved pid. Metadata lookup can therefore fail to find a matching window for a successful capture. Do not assert a guaranteed pid/window consistency check.

Both top-level and app.scaleFactor are read from NSScreen.main.backingScaleFactor, each with fallback 2.0; these are not calculated as outputWidth/windowFrame.width and are not necessarily the target display's scale. Name fallback is `Unknown` when localizedName is unavailable. Evidence: capture selection/error `0x100070ee4–0x100071068`; mkdir/path `0x10007107c–0x10007112c` and `0x10007113c–0x1000712c8`; fast/fallback `0x1000712cc–0x1000713e4`; trust/background `0x100071474–0x100071684`; response construction/scales `0x10007168c–0x10007180c`.

#### Background AX update

When trusted, a background operation creates a separate worker queue named `alma-appshot-ax-worker-<timestamp>` and waits on its semaphore for up to 3 seconds. The worker invokes:

`AXBridge.snapshot(bundle:nil, pid:<resolved pid>, windowId:<captured window>, depth:12, interactiveOnly:false, store:<daemon shared ElementStore>, wakeupSeconds:0.2)`

Snapshot exceptions are swallowed and yield empty AX text. The worker converts snapshot data to text, writes it into a shared string box and signals the semaphore. On timeout the waiting operation writes `[appshot] AX snapshot timed out (pid=<pid>)\n` to stderr, then still sends one update with the box's current text. The worker is not cancelled by timeout; there is no second broadcast in the inspected snapshot-worker closure if it finishes later.

Event:

```json
{"evt":true,"topic":"appshot.update","payload":{"type":"axText","imagePath":"/…/appshot-….jpg","axText":"…"}}
```

`imagePath` is the association key; no command request id is included in this event. No trust means no background worker/update from this path. A capture does not subscribe the caller by itself: monitor_start or some other existing subscription must already have subscribed it to appshot.update to receive this event. All subscribers to that topic receive the update. Scheduling gives no guaranteed ordering between the ordinary response and a sufficiently fast update event.

Evidence: background closure `0x100071f60–0x100072754`, 3-second wait `0x100072488–0x1000724e8`, payload `0x1000725cc–0x100072708`, snapshot call `0x1000731f4–0x100073228`, catch `0x10007322c–0x100073244`, store/signal `0x1000737bc–0x1000737d8`.

#### AX text rendering details

The background worker's text renderer is distinct from the main snapshot JSON serializer:

1. If snapshot.windowTitle is present and nonempty, begin with `# <windowTitle>` and one empty line
2. For each serialized element, create parts beginning with its nonempty `role`, then its nonempty `title`
3. If its `value` is present, nonempty, and different from `title`, append value and skip description
4. Otherwise append nonempty `description` when available
5. If parts is nonempty, append `- ` plus parts joined by the literal separator ` · ` (space, middle dot, space)
6. Join all lines by LF, without an explicitly appended terminal LF

No ref IDs, coordinates, roleDescription, action list, or tree indentation are emitted by this renderer. A nonempty value suppresses description only when it differs from title. Evidence: title/header `0x10007324c–0x100073318`; role/title/value/description collection `0x100073340–0x10007356c`; element separator and prefix `0x1000735b4–0x1000735e0`; final LF join `0x100073788–0x1000737a0`. SerializedElement getter offsets cross-check the loaded fields: role +0x10, title +0x40, value +0x50, description +0x60.

### 6. Appshot event wire format

#### mcp_start argument handling

- `port` read0x10007cdec. Values representable as UInt16 (0…65535) are passed as present. Missing/unconvertible values **and parsed integers outside UInt16 range** become nil at0x10007ce20–ce34. This is a silent fallback, not a UInt16 trap or invalidArg. The underlying NWEndpoint.Port(rawValue:) optional is also coalesced to `.any` when absent (0x100054b74–c4c). No fixed default TCP port is encoded here.
- `token_path` optional String read0x10007ce10; nil selects a default token-file path in start. Empty string is present and is forwarded rather than rejected by requireStr.
- If listener already exists (self+0x18), start immediately returns current status0x10005486c–487c. New port/token_path arguments are then ignored; it does not rebind or rotate the token on this already-running path.
- When stopped, start assigns daemon reference, generates a fresh bearer token and chooses token file: explicit token_path if non-nil; otherwise `(environment["HOME"] ?? NSHomeDirectory()) + path component ".alma/cu/mcp-token"` (0x1000548c8–4a44; literal0x100094860). It writes token via0x100067320 before listener construction. The token value is not returned in status.
- Token write creates parent directories (0x10006745c), writes UTF-8 Data (0x1000674ec), then calls chmod0600 (w1=0x180 at0x100067568). The chmod return is not tested in this function. Filesystem/Network framework thrown errors propagate through the ordinary processLine error conversion; no success should be fabricated on write/bind failure.
- Starts NWListener and waits for boundPort!=0, with a two-second deadline and0.01-second polling sleeps (0x100054dd8–4e70; Double constant0x3f847ae147ae147b). On timeout it cancels/clears listener and throws internalError **`MCP listener failed to bind within 2s`** (factory0x100054f0c, text0x100093650).
- Status advertises `http://127.0.0.1:<port>/mcp`; exact HTTP binding/auth behavior remains separate from this control schema.

#### mcp_allow validation and expiry

- Reads team_id0x10007d214, bundle_id0x10007d230, pid0x10007d24c, ttl_seconds0x10007d350.
- Requires at least one of the three identity optionals to be present. If all nil: invalidArg **`need at least one of team_id / bundle_id / pid`** at0x10007d390 (text0x100094d60). Optional Strings are not trimmed or required nonempty here; an empty string passes presence validation.
- A present pid narrows to Int32; outside[-2147483648,2147483647] hits trap0x10007d4b0/4b4. Within range, no positive-PID check is present at this dispatcher boundary.
- Missing/unconvertible ttl_seconds is forwarded as nil. addWhitelist then stores no expiry (0x100063580–635bc). - Matching rules across team_id/bundle_id/pid and the moment expiry is enforced are deliberately not inferred from add/list alone.

The native standalone MCPServer is not interchangeable with the product's traced JS stdio MCP bridge. Its OAuth grants/peer-whitelist HTTP transport is a distinct optional product capability. Control-shell wire schemas do not establish OAuth or full-RPC interoperability. Keep that backend disabled/unsupported in a core clone until implemented; do not expose an insecure permissive substitute.

Core static protocol/algorithm reconstruction is not runtime verification: TCC, private API behavior, focus races, AX fidelity, ScreenCaptureKit scaling and app launch remain macOS acceptance-test gates. PIP/Appshot/native-extra supplement documents likewise separate static contracts from live OS proof.
