# 合成测试与 macOS 验收


## 这份包证明什么

本包是原创测试设计，不是 Alma 的测试结果，也不是可运行的产品实现。只运行我们编写的数据生成器和通用 JSON Schema 校验器，没有执行提取的 JavaScript、CLI、Mach-O、应用或其服务。`STATIC_EXPECTATION` 表示从静态证据导出的可测试预期，不表示该测试已通过。`UNKNOWN_REQUIRE_RUNTIME` 是阻塞结论的占位值，绝不能当作宽松通配符使测试通过。

本包覆盖静态材料已知的外部边界，不声称穷尽 macOS 的系统状态、私有 SPI 或所有原生算法。每个精确常量来自证据；fixture 自选尺寸、等待预算和像素容差是测试设计，不能反写为 Alma 默认值。

## 严格判定规则

- 先选择 `alma_0_4_164`（对应工程手册 compatibility）或 `safe_profile`（对应 safe），测试开始后不得换 profile
- oracle.expected 是需要逐项断言的观测投影，不是整个工具结果的字节快照。例如 `native_args_forbidden_keys` 检查这些键缺失；`summary_contains` 做子串检查；`image_blocks` 统计 MCP image block；`json_screenshot_key_present` 检查解码后的状态正文，不包括其他 text block
- 字符串 error_class 如 TARGET_MISMATCH 是测试分类，不是推断出的 Alma 错误码；安全实现把它映射为自身 `replica.*` 错误码。额外字段未被断言时不得默认为不存在
- `schema_valid:true` 只表示输入 schema 接受；不保证 handler 必要参数检查通过，不保证 ref有效，更不保证事件发生。例如 click最小对象通过字段schema，handler随后仍可拒绝
- `null` 与省略不同。原 schema 转录未断言 unknown-property stripping 行为，本包不补猜。NaN/Infinity不是JSON，不应伪装成JSON向量
- 向量中的 fixture:// 路径由 mock filesystem 解析，禁止当真URL或真实磁盘路径读取。010203故意不是JPEG：用于证明原包装不校验图片内容；图像质量测试使用夹具生成的有效JPEG
- 同一用例中多个可异步排序事件，应按规定偏序断言；只有已证顺序才能要求全序。未知动态竞态用运行证据闭合，不能凭mock选择一个结果
- runtime未知项即使采到了截图也仍为 INCONCLUSIVE，直到接收端、焦点、指针、最终状态和原始响应相互吻合

## 分层 oracle，禁止“看起来成功”

L0：输入是否被schema接受。L1：包装究竟发送了什么cmd/args、向谁询问批准、是否补图。L2：daemon是否接受、回复、超时、断线。L3：接收端收到什么及真实状态变化。L4：前台用户焦点/键盘/真实鼠标是否受影响。L5：UI和模型是否准确呈现L2/L3的结果。每层单独报告。

不允许以下推理：有 `ok:true` 所以点击有效；MCP没有isError所以按键送达；CLI打印成功所以输入完成；UI有✓所以事件有效；显示新截图所以ref未失效；cancel返回所以native停止；showInactive存在所以绝无瞬时焦点变化；native配置showsCursor=false所以所有capture路径都无硬件鼠标。

## 无重放约束

所有profile均须记录每个mutation的dispatch次数。超时、取消、断线、图片失败后，禁止自动再次发送click/type/drag/press/scroll/set_value等变更。测试控制器也不得因为结果未知而重试同一次动作。若需重跑，先停止/确认旧请求结局、创建新run_id、复位夹具、记录独立op_id，并将其记为新实验。截图失败只重做经明确授权的只读观察，不把原动作一并重跑。

## 受控环境与权限

未来动态阶段仅对独立测试应用、合成文本、合成文件和专用测试桌面执行。TCC授予、系统权限修改、锁屏/解锁、私有SPI实测需要相应用户授权；fixture清单不构成授权。不得操控真实账户、支付、聊天输入框或密码窗口，不得将用户桌面作为可分享的截图样本。

锁屏、protected media、Secure Input、不支持的系统版本、缺权限均为独立能力条件；不得绕过保护来“修好”测试。safe版本在不能证明安全/目标身份时返回明确不可用且不投递。compatibility对原样行为未知时记为UNKNOWN，不能复制假想的绕过策略。

## Runtime-01—12验收规则

1. RUNTIME-01 身份：run_id/op_id、profile、样本hash或复刻commit、macOSbuild、架构、屏幕布局、权限、fixture版本齐全；缺任一关键项为INCONCLUSIVE
2. RUNTIME-02 接收：在已声明支持的场景，只有预期控件产生一次预期逻辑状态变化；无关控件/旁路前台app无变更。AX动作可以没有mouseDown，但必须有匹配控件状态/AX action见证
3. RUNTIME-03 无重放：每个op_id只派发一次变更；timeout/cancel/截图失败后dispatch仍为1或未启动时0，不得大于1
4. RUNTIME-04 输入完整性：文本按Unicode标量与原始UTF-16两种方式存档；普通文本框最终字符串必须与指定插入/替换语义精确一致。组合输入/IME另列，不把规范等价默认为字节相等
5. RUNTIME-05 释放：正常和异常路径结束后，测试记录没有未配对的已观察key/button down；观察器不可见或进程崩溃造成缺测时为INCONCLUSIVE，不能判通过
6. RUNTIME-06 焦点：被动后台能力声称不抢焦点时，前台bundle/window序列与焦点通知中不得有目标/镜像瞬时激活，旁路输入接收完整。只有轮询无事件日志不能证明零瞬时切换；报告采样盲区
7. RUNTIME-07 光标：hardware cursor与ActionCursor/Lens三条轨迹独立存档；无物理鼠标移动能力只有在硬件轨迹未变化且测量覆盖时通过。show_cursor=false不是其替代断言
8. RUNTIME-08 截图：新capture_id文件可解码、尺寸与元数据一致、不是前一代图片；四角标记/中心标记落在测试选定容差内（几何误差≤1 screenshot pixel，JPEG颜色不要求逐字节相等）
9. RUNTIME-09 隐私：safe窗口截图不得在失败时悄悄切到全桌面；若启用桌面回退需明示范围。原mirror窗口失败→display fallback只在compatibility隔离夹具中验证
10. RUNTIME-10 取消：dispatch前取消不得有接收端变更；dispatch后允许已执行部分，但必须完整记录、释放输入、标明实际或未知结局，不得无证据声明回滚/终止
11. RUNTIME-11 资源：关闭后没有新的所属轮询/流租约，旧generation的迟到完成不能重新开窗或发布帧；原静态已知竞态在compatibility中标观察结果，不偷偷套安全版本要求
12. RUNTIME-12 能力矩阵：每个系统/场景独立列supported/unsupported/unverified；只有满足该场景全部相关oracle才可宣称支持。默认可见窗口通过不外推到遮挡、最小化、锁屏或多屏

## 已知阻塞点

- 真实窗口遮挡/最小化/锁屏和跨Spaces可用性；系统版本与私有事件投递的稳定性
- native队列、socket断开、取消、shutdown时已排队事件的结局
- OCR触发已确认：成功截图且原始snapshot.elements.count≤1；不是diff结果数。原生命令字面量为snap，普通MCP动作补图为get_app_state(depth=0)，两者不可混同。仍需运行验证OCR坐标与系统行为

# 先做这39项，再展开矩阵

不要按734条从头跑到尾。总数分为453条机械生成schema排列、113条逐项编写的契约场景、168个运行环境矩阵格。没有任何产品测试已运行或通过。先看主工程手册模块依赖，再做 `p0-critical-subset.json` 的39条静态可判定检查。

这39条按schema→transport→target/state→diff→images→approval→UI顺序排列。它们只需要原创建造的fake daemon、fake filesystem、fake HTTP和虚拟时钟，不能启动Alma。`check_p0_observations.py ACTUAL.json` 是可执行的判定器，不是产品实现或自动驱动器。它对真实实现的独立观测做严格投影比较；不能把expected文件复制成actual作为测试。

ACTUAL.json以case ID为键，每个值为预期结构对应的实际观测。额外未断言字段允许存在；所有预期字段必须存在；数组顺序和长度精确；boolean不能以0/1冒充；数值精确。几何输入选择了可精确表示的数值，P0不使用宽松浮点容差。完整OS截图的±1px规则另见README。

## 观测采集约定

- schema_validator：将input.args交给待实现schema，记录schema_valid；scope写固定文字以区分schema与行为，禁止调用handler
- daemon_client_fake_bytestream：先建立input.pending对应调用；推进输入字节、close和虚拟时钟。resolutions/rejections必须由promise回调记录；pending_after来自可观测诊断接口；重放次数由write spy计数
- MCP_handler_fake_daemon：按input.setup设置index/HTTP/mock响应；其他P0 case统一无playbook、focus权限健康、approval=true、mutation RPC ok={}、postshot RPC ok={}。启动一个handler，完整记录RPC payload、批准query、补图目标与调用次数。只比较明确字段，不把UI文本当接收成功
- sky与StateDiff纯函数：注入input.prior_refs或baseline；分别记录renderer文本/index array或diff实际输出。`disabled_resets` 必须连续调用同一diff实例，不能为第二次创建新实例
- MCP图片：fake readFile由fixture://映射读合成bytes；实际content block解码后投影为image_blocks、filesystem_read_count、JSON字段存在性及实际base64/MIME。不得补做JPEG合法性检查来“修正”compatibility
- approval：HTTP spy给指定status/body；gate进入内函数计dispatch_allowed；拒绝时检查内容有无isError和log/PiP调用。approved=true与truthy不等价
- UI：从空stack或case指定tombstone开始；只注入虚拟clock并触发指定事件。ring坐标由实际布局函数返回，不从expected复制
- null字段在这些投影中表示“不适用”，不是要求真实MCP新增null字段。例如审批允许时denial_log_and_pip_calls投影为null，避免把成功调用次数误作拒绝路径断言

前提/观测接口不满足时标NOT_RUN并补测试驱动，不修改expected来迁就实现。P0全部通过仍不能宣称后台操作、锁屏抓图或无焦点抢占成立；S3以后的受控macOS证据是这些能力的硬门槛。

P0新增5项：UTF-8字节内部拆分、超时迟到只本地拒绝且不重放、safe重连清buffer、safe未知结局、safe目标绑定。前三十二项为compatibility契约，最后五项中后三项明确为safe要求；它们不是safe产品发布的完整最小集合。发布仍按S3—S7能力与见证门槛。UTF-8用receive_chunks_hex逐段解码为bytes再喂framer，禁止每段先转Unicode字符串。超时测试只断言本地状态，不推断native副作用。

最后两项（现为39项）验证跨层v*可达性：普通click(ref=v1,bundle=fixture)不得被fake daemon直接假设成功，应接入native dispatch的resolveActionPid分支模拟，并在缺pid/bundle时报精确invalid_arg；visual cache的存在不能救活该请求。sky状态含visual_regions但elements为空时，索引必须仍为空。两项均是兼容负例，不意味着安全实现也应丢失目标。
