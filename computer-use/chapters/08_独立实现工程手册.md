# 独立实现工程手册

## 目标与实现模式

本章规定一个可分工、可测试、可停止的独立实现。它是基于已还原契约作出的工程设计，不是 Alma 原仓库结构。不得把本章选定的文件名、类型名、串行队列或安全策略反写成原产品事实。

先实现可重复的协议与状态模型，再接 macOS，最后接宿主和 UI。初版只做 macOS Computer Use；不引入聊天、计费、云端账户、插件市场、第三方模型登录等无关产品功能。Electron 宿主只承担本地 HTTP、MCP 适配、图片内容转换、授权、镜像与 Appshot。

每次构建必须显式设置 behaviorProfile，唯一合法运行值为 alma_0_4_164 与 safe_profile，与conformance目录一致。本章“兼容模式”指alma_0_4_164，“安全模式”指safe_profile；英文compatibility/safe只是解释性别名，不能出现在配置。alma_0_4_164用于隔离实验复现已知包装差异；safe_profile仅是面向实际使用的设计候选；本次运行选择仍为UNSELECTED，未自动选定任何profile。禁止在同一测试中偷偷混用两个profile。涉及未知或私有SPI，未通过批准的macOS验收前必须标为unavailable，不能用一次成功包装成支持。

compatibility 不意味着允许绕过操作系统权限、攻击真实账户或复制专有代码。它只意味着在授权测试夹具内尽量匹配已观察到的功能边界。对于已送出的事件，任何 profile 都不能声称可回滚。

## 工程启动工单零

此步骤是后续所有工单的硬前置。当前交付是静态研究与实施文档，没有在用户Mac上创建项目、安装工具链、签名或改变TCC。执行模型不得凭文档存在推断环境已具备。

下列是独立重实现选定的参考技术栈，不是恢复出的Alma构建仓库。目标运行基线固定为macOS14及以上、ARM64。helper plist允许13是原样本metadata，已检截图路径在13抛错，因此新实现不把13列入支持矩阵；如果需要13，另开降级捕获工单并标safe偏离。x86_64/Universal另作第二阶段，不把ARM64静态地址当x86代码。

在实施机上只读收集sw_vers、uname -m、xcodebuild -version、xcrun swift --version、xcrun --find swiftc、node --version、所选包管理器版本，写toolchain-lock.json。Swift语言模式先固定5，Package.swift的tools-version为5.9，deployment target macOS14；实际编译器必须支持该manifest。参考依赖候选固定Electron38.7.2、@modelcontextprotocol/sdk1.24.3、pnpm10.14.0：分别来自当前样本Electron Framework Info.plist、已安装SDK manifest、app packageManager字段，属于样本证据，不是新仓库已编译验证。SDK manifest要求Node>=18；实际构建Node版本必须只读采集后锁定。bootstrap执行方先在全新目录用精确候选生成不可变lockfile，运行空host启动、stdio初始化/listTools、Zodschema验证、image/isError转换的最小API兼容测试。若版本无法获取或API不兼容，写dependency-blocker记录失败/候选替代/影响并STOP待负责人接受；不得自行升级漂移。通过后把确切Node、Swift、Electron、SDK、pnpm版本和lockfile hash写toolchain-lock.json。禁止使用latest、^、~或让后续模型各自挑版本。若没有可用工具链/依赖下载授权，STOP bootstrap，不能把伪命令记为已运行。

## 安全模式的固定设计常量

以下值是为了减少后续实现选择而固定的独立设计，不是逆向发现的Alma常量。初始配置写入contracts/safe-policy.json：maxNativeFrameBytes=8388608（8MiB）；maxImageBytes=16777216（16MiB）；maxImagesPerMessage=4；maxActiveThreadImageBytes=134217728（128MiB）；maxTotalImageCacheBytes=1073741824（1GiB）；maxTextLogValueChars=0（默认不记输入文本）；approvalTimeoutMs=5000；defaultRpcTimeoutMs=20000；captureRpcTimeoutMs=30000；maxConcurrentActionsPerTarget=1；liveInputEnabled=false。所有上限超出都返回明确错误，不截掉JSON/图片后当成功。

安全模式用full SHA256作图片asset identity，临时写入后原子rename。cache预算不足先清无持久消息引用的最旧资产，仍不足则拒绝新写并返回replica.cache_full；不得删活跃消息资产或让mapping指向别图。处理文本日志只记长度、可选不可逆摘要和结果，不记正文。生产权限/隐私需求改变这些值时，更新decision和测试，不在实现中散放magic number。

请求在validation/resolve/authorize前取消，outcome=not_started；已进入dispatch但无完成证据则unknown；调用返回只证明接受时为effect_unverified；只有fixture或后续状态明确证实时verified。默认绝不输出“已停止所有动作”。safe_profile的错误code以replica.开头；原有code/hint作为可选cause保留。取消不回滚、不自动重放。兼容模式保留原包装的无signal语义，但只在隔离测试使用。

## 统一类型边界

这些是独立实现的内部类型选择。对外仍按各入口契约序列化，尤其不能把内部更丰富的错误字段偷偷当成 Alma 已证输出。

JSONValue = null | boolean | number | string | JSONValue[] | {[key:string]:JSONValue}。编码器不得输出 NaN/Infinity；compatibility 的 CLI 转型应单独测量其转成 JSON null 的边角，不能让内部数值类型被污染。

RequestEnvelope = {id:string, cmd:string, args:object}是独立实现内部规范化后的类型；原生wire允许args省略或null，decoder应先按原契约接受，再在内部规范化，不可用该内部类型拒绝原输入。客户端正常生成 16 位 hex id；服务端是否严格限制该格式必须作为独立策略，而非假定原产品已校验。每帧为 UTF-8 JSON 加 LF。ResponseEnvelope 为 {id:string, ok:boolean, data?:JSONValue, error?:NativeError} 的内部表示；原产品真实错误字段位置以 native 命令附录为准，适配层必须逐字段对照，不能靠这个内部类型推断。

NativeError = {code:string, message:string, hint?:string, phase?:string, outcome?:string}。后两个字段属于安全实现的扩展：phase ∈ validate/resolve/authorize/observe/dispatch/postobserve；outcome ∈ not_started/accepted/effect_unverified/verified/unknown。没有原样错误码证据时，在兼容入口不要编造 Alma error code；在自有入口用明确命名空间 replica.*。

TargetRequest = {bundle?:string, pid?:integer, windowId?:integer, ref?:string}。ResolvedTarget = {pid:integer, bundle?:string, windowId?:integer, source:bundle|pid|ref, evidenceGeneration?:string}。safe profile 一次解析后把同一个 ResolvedTarget 交给批准、动作、截图和日志；目标冲突直接返回 replica.target_mismatch，且不得执行动作。compatibility profile 保留各包装已证的目标拆分，限测试使用。

SnapshotKey = {pid:integer, windowId:integer|null}；序列化为十进制 PID、冒号、十进制 windowId 或减号。ElementRef 为不透明字符串，禁止调用者解析其中计数推断有效性。ElementDescriptor 包含 role、可选 subrole/title/identifier/roleDescription、parentRoles。ElementEntry 包含 live AX handle、snapshotId、pid、可选 descriptor、invalidated。

ElementRecord 内部至少包含 ref、role，以及可选 subrole/title/value/description/role_description/enabled/focused/children_count/actions/bounds。bounds 的单位必须带类型标识 ScreenPointRect 或 ScreenshotPixelRect；禁止通用 CGRect 在边界处无单位传递。完整原生输出的可选字段与 Swift 的字符串化行为要通过命令契约和 golden fixtures 校准。

ScreenshotArtifact = {path:string, pixelWidth:integer, pixelHeight:integer, capturedRectPoints:Rect, target:ResolvedTarget, capturedAtMonotonicMs:number}。内部路径和 mapping 必须一同提交；图片写失败不能更新映射。外部 screenshot.path、data_url、url 三个字段绝不互相假定等价。普通 MCP 读 path；sky 状态优先 data_url 再 url；宿主/CLI另按契约处理。

CancellationToken = {requested:boolean, reason?:string}；ActionReceipt = {accepted:boolean, delivery?:boolean, outcome:enum, method?:string}。token 只是协作取消信号，不是停止 OS 已排队事件的证明。进入 dispatch 后失去响应时使用 unknown；禁止自动重放 click/type/drag/press/set_value。

## 接口签名与所有权

以下签名固定模块责任；不是要求采用某个未经验证的第三方库。

Transport.connect() -> Connection；Transport.call(command,args,deadline) -> Promise<NativeResult>；Transport.close() -> void。只有 transport 能写 socket 和修改 pending。单元测试注入 ByteStream 与 MonotonicClock；禁止直接睡眠等待来测边界。

TargetResolver.resolve(request,mode) -> ResolvedTarget。输入字段的 schema 校验在 adapter；OS 存活性、bundle 到 PID 和窗口归属检查在 resolver。ref 解引用只有 ElementStore 能做。若 ref 所属 PID 已退出，不能退化成全局前台操作。

PermissionService.inspect() -> PermissionSnapshot；PermissionService.request(kind) -> PermissionRequestReceipt。授权请求返回不代表已授予；随后必须再 inspect。不要把 UI 批准记录复用为 TCC 状态。

ElementStore.beginSnapshot() -> SnapshotId；register(axElement,pid,descriptor) -> ElementRef；resolve(ref) -> Entry|Failure；clear() -> void。store 拥有 observer/run loop source 生命周期。SnapshotBuilder 只能通过 store 注册，不能自己生成 eN。实际调用 AX 的线程/主 run loop 安排必须通过 macOS fixture 验证。

SnapshotBuilder.capture(target,options) -> FullSnapshot；StateDiff.apply(key,fullElements,disabled) -> DiffResult。先获得 fullElements，再在 diff 层产生 changed/removed/unchanged；不要直接遍历时构造差分，因为删除项需要对照完整新 ref 集。

CaptureService.captureWindow(target,options) -> ScreenshotArtifact；captureDisplay(display,options) -> ScreenshotArtifact。CoordinateMapper.commit(artifact) 原子更新 mapping；toScreen(pid,pixelPoint) -> ScreenPoint|NoMapping。compatibility 用 PID key；safe 推荐使用 snapshot/window 绑定的 mapping id，并要求动作引用对应 mapping，作为明确协议扩展。

AXActions.click(entry,options) -> ActionReceipt；PointerDispatcher.click(target,screenPoint,options) -> ActionReceipt；KeyboardDispatcher.press(target,keySpec) -> ActionReceipt。三者不得悄悄激活目标 app；如某能力只能靠激活实现，需单独能力/明确允许，不能作为后台路径的隐藏回退。

FocusGuard.begin(scope) -> GuardLease；GuardLease.close() -> void；FocusGuard.health() -> Health。close 必须可重复调用。arm 失败是可观测结果，不能吞掉并声称零焦点抢占。健康警告的缓存只属于包装展示，不改变 guard 真正状态。

PipStack.present(item,automatic) -> PresentResult；dismiss(id) -> void；invalidate(id) -> void；hideProgrammatically() -> void。PipStack 不采图；FrameSource 只采图；Renderer 只展示。每个资源 lease 都有 owner id 与 generation，safe profile 用 generation 忽略旧异步完成。

AppshotController.arm(hotkey|null) -> State；captureNow() -> CaptureReceipt；Composer.consume(token,capture) -> void。capture 文件、动画、IPC、附件处理分别回报失败；不能把显示动画当作附件已就绪，也不能自动发送用户消息。

## 依赖顺序工单

每张工单只有在 exit 条件可展示时才结束。下列步骤不是估时，禁止因“编译通过”跳过后续的行为验证。附带 conformance 目录提供 fixture 与用例；把当前工单对应要求 IDs 写进提交说明。

### 工单 01 固定证据与兼容表

输入：样本 manifest、组件 hash、工具/CLI/native/HTTP 契约、审计报告。输出：docs/decisions/0001-scope.md 与 compatibility.json。逐项登记原行为、证据定位、safe 差异、未决点。建立 requirements 的实现文件链接，暂不写 OS 操作代码。exit：所有公共工具、CLI命令、HTTP route 都有唯一 owner；未闭合项有 STOP 状态。

### 工单 02 JSON 值与分帧

仅修改 Protocol/Envelope.swift、JSONLFramer.swift、测试。按字节累积，只有遇 LF 才解码完整行；同一 read 可以产生多帧，单帧也可以跨 read。测试跨 UTF-8 多字节字符拆分，避免把分片先转 String 导致替换字符。safe profile 设最大帧限制并在重连清空 buffer；compatibility 记录原客户端未见限制/未清空的差异。exit：分片、合并、空行、坏JSON、无LF、超限测试都有结果。

### 工单 03 客户端状态机

仅实现 daemonClient 和 fake daemon。状态为 disconnected/connecting/connected/closing；并发 connect 共用 promise；pending 按 id 管理。默认20s，显式状态/补图30s，连接等待与请求计时分开。late/unknown id 忽略；断连拒绝全部pending；请求超时不重发。exit：虚拟时钟能逐 tick 证明只 resolve/reject 一次；取消时不会自动构造 native cancel。

### 工单 03B 守护进程路由与 Ping

依赖02和03。在自有CUDaemon实现AF_UNIX listener、连接context、RequestRouter白名单与纯ping/diagnostic handler；此时不注册真实输入handler。连接任务顺序与并发行为按原native章，在safe_profile加帧长限制与独立connection epoch。ping返回独立产品名、版本、能力与测试profile，不冒充Alma。用03的客户端对自有临时socket做ping round-trip，再测坏JSON、半行、两peer、断连/短写/清理；这些通过才进入04。exit：请求id一一对应，错误无副作用，server可正常退出并只删自己socket。

### 工单 04 纯工具包装

接 mock daemon 与 fake HTTP，不接 macOS。逐个照 tool-inputs 和 payload_contract 写 handler，保留普通/sky 不同默认、schema上限、gate、图片格式、summary语义。不要先写通用 normalizeEverything 再套所有工具。exit：所有23工具有合法/省略/错误/边界测试；ref-only 不补图、window-only 不补图、sky path-only 无图、delivered=false非异常均可复现。

### 工单 05 本地 HTTP 和 CLI

先 route mock，再 CLI。按 cli-command-catalog 区分位置参数、命令别名与共同预解析。--json 不是统一原样输出模式。safe profile 的严格数值输入单独显式记录。exit：22 canonical 功能命令、help 与 launch别名均覆盖；每条调用顺序和退出码可由mock断言。

### 工单 06 测试应用与权限诊断

先建立合成 AppKit/浏览器 fixture，再接真实系统。界面元素有稳定标识、可控制的销毁/重建、重复标题、滚动区、菜单快捷键、无AX画布和可见事件计数。PermissionService 先只读状态，再通过人工批准步骤验证 request。exit：测试 app可以报告前台/按键/鼠标/焦点/文本变化，且拒绝权限时无静默成功。

### 工单 07 AX 存储与恢复

以 mock AXHandle 的稳定 identity 先测 beginSnapshot、register 和 descriptor 搜索，再接AX对象。ref在同PID+CFEqual且当前snapshot尚未使用时复用；销毁/无效分支按native章实现。恢复必须有200节点、12层、最近3祖先role与唯一候选限制。exit：零候选和多候选都失败；禁止选择第一个看起来相似的元素。

### 工单 08 AX 快照和差分

先做全量输出再做 diff。独立纯函数实现固定字段指纹、bounds整像素取整、PID/window key、removed_refs排序。禁用diff仍更新基线。exit：新增/修改/删除/不变/窗口切换/禁用重置/subpixel边界都有golden结果；sky如何忽略删除另在adapter测试，不能改native来“补救”。

### 工单 09 截图与坐标

依次完成 window shot、display shot、JPEG写盘、mapping发布。用明确point与pixel类型；公式见native章。先用合成矩形测，再跑1×/2×/混合DPI/负坐标屏幕。exit：针对每张截图的已知标记，转换落点在容差内；发生窗口切换或mapping不存在时不静默用屏幕坐标。

### 工单 10 OCR 状态补充

按最终native章的触发门槛与VisualIndex契约接Vision；只在证据明确的内部路径触发，不凭空注册公开ocr工具。OCR ref 与 AX ref 路径分开，不对视觉框执行AX set_value。exit：空、单节点、多个AX元素和无文字图像的门槛用例明确；OCR边框原点/缩放/最大结果数符合测试。

### 工单 11 AX 动作

先set_value/select_text，再ref点击/secondary/scroll。每项检查角色/支持action/目标PID，按原native章决定AX路径和物理回退。返回accepted与effect分开。exit：fixture记录目标控件改变，失败仍能区分no_ref、stale、unsupported、system_error；不会把失败回退到当前前台app。

### 工单 12 指针输入

严格按native静态算法与已验证SPI前提实现。safe_profile要求每次down有清理路径尝试up；原alma_0_4_164拖拽最终up仍可能创建失败且未证无条件补偿，兼容用例应记录该结果而不是悄悄套修复。拖拽插值使用明确时间和坐标。show_cursor控制显示层并不等于不动硬件指针，需实测分开记录。exit：后台/遮挡/目标退出/中途取消/多按钮/拖拽异常不会留下卡键卡鼠标；无法验证的私有字段不填猜值。

### 工单 13 键盘与文本

先key parser与modifier规范化纯测试，再菜单快捷键AXPress，再前台/可投递路径；Unicode事件按最多20个Unicode scalar分块；select_text/AX range使用UTF-16单位；布局翻译按完整Swift Character匹配。三种计数不能混用，emoji不得拆代理对。不得用剪贴板替代未证实的输入机制。exit：emoji/组合字符/CJK、前台与后台、菜单命中/禁用、delivered=false都被fixture真实记录；包装摘要与实际效果分别断言。

### 工单 14 焦点防护

实现guard lease、事件tap健康状态与temporary activation allowance；以主动前台测试app持续输入作为旁路观察器。exit：成功、arm失败、tap禁用/重启均有证据；报告记录焦点变化次数，无法确保时标能力受限，不能只看showInactive就判通过。

### 工单 15 宿主模型输出与停止

接MCP client、toModelOutput、图片落盘/再水合和watchdog。compatibility呈现原isError损失；safe保留结构化失败。外层停止、MCP取消、socket断开和native事件继续是四个独立观测量。exit：文本模型/视觉模型、坏图片、图片读失败、watchdog超时、迟到响应都有明确结果；不再用terminated作无依据保证。

### 工单 16 被动镜像

先只用合成frame source完成stack，再接computerPump/CDP lease。固定关闭抑制键、滑动600000ms、420ms删除、90s活动与333ms/220ms双循环。exit：持续活动超过10分钟不意外重开、手动打开清抑制、source切换/失败/在途关闭无资源泄漏。原竞态在compatibility中是待观察行为，safe用generation修正。

### 工单 17 Lens 与原生 PiP

将其当成单独组件，不把Electron镜像重新命名成native PiP。Lens默认、ActionCursor记录时点、窗口流硬件cursor行为都按native展示报告。exit：关闭和释放只影响所属lease；模拟光标与硬件cursor分别可测；关闭设置不被误当成禁止系统事件。

### 工单 18 Appshot

实现arm/disarm、capturingNow、request id、target选择、1100ms动画与715ms发送、消费token、AX上下文迟到、附件失败。这里允许的显式聚焦Alma行为与被动镜像不同。exit：重复热键只产生一个有效捕获、附件不会自动发送、早到/迟到context规则清楚，授权失败不会假称active。

### 工单 19 全链闭环

执行conformance staged plan，从合成工具输入到fixture效果再到模型可见结果留同一correlation id。每个已承诺能力均有证据；每个失败均能落到已知层；所有P0安全门槛通过后才允许真实工作流试用。exit：形成一份按OS版本、架构、显示器配置、权限身份记录的运行报告，而不是只展示一次成功视频。

## 模型执行纪律与停止条件

每次给执行模型只交付当前工单、所需契约、相关算法、对应fixtures和上一步结果。提示它先复述字段优先级与已知未知，再写最小实现；复述不一致时先纠正，不允许一口气生成全项目。

每次提交必须附：改动文件列表、对应requirement/test IDs、已运行命令与真实输出摘要、未运行测试、profile、安全偏离、下一步。没有运行环境时只标“未运行”；不要用“应当通过”替代结果。

遇到下列情况停止该工单并输出阻塞记录：证据互相冲突；native分支来源不明；缺少私有SPI签名或字段含义；没有macOS权限/签名身份；无法确定坐标单位；测试需真实私密数据；需要用户没有授权的外部通信/安装/权限更改；代码无法证明事件释放。可以继续独立的纯函数工单，但不能在未知处编一个行为再宣称兼容。

阻塞记录格式固定为：requirement_id、evidence_used、missing_fact、why_it_changes_behavior、safe_temporary_behavior、next_observation、owner、status。临时行为默认拒绝该能力并给出可诊断错误，而不是静默降级到更广目标。

未知项被补证后，先更新契约和fixture，再改实现。不要把一次运行结果覆盖静态已证的所有分支；一个fixture只证明其OS/目标app/权限/显示器条件下的行为。

## 最常见的复刻错误

- 仅把23个MCP函数做出来，忽略HTTP/CLI另一条路径和native状态
- 把bundle、PID、ref、window_id当成四种等价目标
- 用截图宽度除屏幕宽度代替当前截图mapping
- 每次snapshot清空ref表，使sky索引与后续操作失效
- 把diff元素列表当全量树，或者遗漏removed_refs和基线reset
- 自动重试超时click/type，引发重复输入
- 把收到取消通知等同于系统事件已停止
- 只看HTTP200、MCP isError缺省、日志✓或CLI成功句判断效果
- 把OCR类名、Lens类名或PIPSession符号的存在当成每次调用实际经过该路径
- 把show_cursor=false、Lens off、没有显示光标、硬件指针未移动混为一谈
- 使用无真实前台旁路监测的单次录像证明绝不抢焦点
- 将整屏截图回退隐藏在成功结果中，没有注明可能扩大可见范围
- 镜像关闭只销毁窗口，不取消或隔离采集中的晚完成
- 将Appshot文本作为高优先级指令，或捕获后自动发送聊天
