# WiseStudio / Lawrence 后台操作手册

## 实测基线与适用范围

2026-10-09 的 LAWRENCE-TOUR 共执行 80 次操作：61 次成功、19 次失败；成功片段合并为 8 分 16.7 秒视频，达到本轮预算上限。主要导航与若干二级页已覆盖，**不是所有控件或原生菜单的穷尽验证**。完整操作、画面和录像在仓库的 `computer-use/field-e2e/lawrence/`，尤其是 `LOG.md`、`evidence/` 和 `out/summary.json`。

当轮目标是 pid **86359**、bundle `com.github.Electron`、window_id **234415**，标题 WiseStudio，桌面 bounds **(156,33), 1309×874**。这些是当轮定位值，不是永久标识；后续任务先核对进程和窗口。不要只凭通用 Electron bundle 选择应用。若用户固定了 pid，始终使用那个 pid，不换进程。

初始页面是：设置 → 网关 → 渠道 → 自定义渠道，渠道筛选为“全部”。最后恢复了这个页面、窗口位置和大小，清除了本轮测试搜索，没有遗留对话框。

本轮两个末态异常需要保留事实边界：

- 076 后观察到 WiseStudio 成为前台、实际鼠标位置改变，来源未定；暂停界面操作，随后只读确认前台回到 Paseo 才继续。不能宣称本轮全程前台和鼠标状态不变。
- 最终邮箱渠道显示 `Command failed`，初始为已连接；本轮没有点击现有账户的连接开关或修改其配置，没有尝试重连。页面恢复不等于外部服务运行状态完全相同。

## 先读手册，再看当前状态

开始前通过 `minami_computer_use.Skill` 读取：

1. `computer-use/screenshot-coordinate-clicks`
2. `computer-use/error-recovery`
3. `computer-use/context-menu-driving`

每次操作前先截图；例如当轮参数：

```js
get_app_state({
  pid: 86359, window_id: 234415, auto_launch: false,
  depth: 20, interactive_only: true, screenshot_max_width: 1280
})
```

**浅树不等于应用永远没有 AX。** 开始时 depth 2～6 主要只有 AXGroup 和窗口按钮，约 4 个交互元素，必须靠截图定位。打开原生头像上传弹窗后，depth 10 发现了 AXWebArea；depth 20 返回 228 项，包含 AXLink、按钮和输入框。后半程的导航基本靠 AXPress 成功。无法单凭本轮确定是加深深度、辅助功能唤醒，还是二者共同作用；后续先尝试一次 depth 20，不保证每个启动状态都立即有完整树。

`elements_are_diff=true` 时，合并变化元素、`removed_refs` 和前次快照；空 elements 可能只是无变化。不要把空 diff 当作控件不存在。所有 `eNNN` 都是本次快照上下文的引用，不能把本手册的实验编号或旧 ref 当永久 ID。

## 稳定的操作选择

| 当前控件 | 优先方法 | 本轮证据 |
| --- | --- | --- |

| 普通按钮、未暴露 AX 的标签 | 刷新截图后点按钮中心 | 003、006～012、022～024；效果以事后截图为准 |
| 搜索或可编辑 AXTextField | `set_value({ref, value:"codex-tour-01", pid, window_id})` | 031 真实落字并过滤到 0，032 清空恢复 7 条 |
| 原生文件选择框取消 | 加深快照，找当前 enabled、title=取消 的 AXButton，AXPress | 025 坐标失败，026 AX 成功 |
| 下拉选项 | AXPress 展开；只看不改值时用其他导航退出 | 036 工作区路径、044 语言下拉 |
| 带菜单项的快捷键 | `press_key`，检查 delivered / suppressed 和实际画面 | 017、018 菜单已投递但无可见效果；078 明确 suppressed |
| Web 长页面滚动 | 先确认存在支持 AXScrollDownByPage 的容器 | 008 对窗口 ref 滚动报错；本轮没有验证 Chromium 长页滚动绕法 |

不要对没有 AXPress 的容器盲试 ref 点击。`strategy:"ax"` 不是通用动作接口。`type_text` 回 `typed ...` 也不是落字证据：005 Unicode 输入和 030 ref+AX 输入均未改变字段；031 的 `set_value` 才成功。

像素点击有一个本轮可解释但未完全证明的限制：`Sources/minami-computer-use/Input.swift` 的后台 click 会设置 Command 标志，而部分 SPA 链接对修饰键点击不导航。这与本轮“只出现悬停样式”的现象相符；不要把它升级成已证明的 WiseStudio bug，也不要改 daemon 或取消后台保护来绕过。使用当前 AXLink 的 AXPress 是已验证的办法。

## 成功操作配方

### 后台进入一个业务页

1. 核对 pid、window_id、bounds 和当前截图。
2. 浅层只见窗口按钮时，加深到 depth 20，按 `description` 找链接；无标题主侧栏链接按当前 AX bounds 与截图图标匹配。
3. 明确是 AXLink 且支持 AXPress 后，使用 `strategy:"ax"`。
4. 等待加载并再次 get_app_state。检查页面标题/选中项/关键控件；加载动画只能证明导航发生，不能证明内容可用。

### 搜索输入并清理

1. 深层快照找当前搜索 AXTextField，确认不是配置字段或消息发送框。
2. `set_value` 写测试值 `codex-tour-01`，观察文本和筛选结果。
3. 同一当前字段 `set_value` 写空串，再截图确认清空和列表恢复。
4. 不用 cmd+a + type_text 清理；后台普通按键可能 suppressed，输入也可能没有真正落字。

### 打开表单后退出

只操作明确的新建/配置入口，确认出现表单后检查其控件；不要提交保存/创建/发送。优先找当前 title=取消 的 AXButton。原生文件选择框需要更深的树。自绘 Close 无效时，使用已验证的取消或返回导航，不用 cmd+w 误关主窗口。

### 每次操作录成功片段

1. get_app_state 截图并选目标。
2. 后台启动固定窗口录像：`screencapture -l 234415 -V 8 clips/NNN_action.mov &`。预期较长操作可取 6～12 秒；编号连续递增，失败编号不重用。
3. 用 MCP 执行该操作，保持窗口不移动、不缩放；不要加 `-P` 或 `-u` 打开播放器/录屏 UI。
4. 确认录像进程结束，再截图检查效果。首轮沙箱内 screencapture 报 `dispatch_source_create returned NULL`；在已有录屏授权的执行环境下重试成功。不要静默把没有视频的操作计为保留片段。
5. 成功保留；suppressed、报错、无效果删除该次片段，但保留日志和状态证据。取消本身如果确实关闭弹窗，是成功清理，效果栏注明“弹窗取消”。
6. ffprobe 校验所有保留片段，按编号生成 concat 列表后合并；concat copy 时间戳告警与解码失败分别记录，不隐藏。

## 安全边界与未覆盖项

这些限制针对“只读探索/不改真实数据”的巡检任务；不要把巡检限制当成用户另行授权真实操作时的永久禁令。

- 后台操作不激活、不 raise、不移动实际鼠标，不移动/缩放窗口。看到前台或光标变化时记录观察，不能无证据归因。只读检查回到后台后再继续；不要抢回或恢复用户前台。
- 不点击现有渠道电源、白名单开关、加入/移除、服务停止/重启、账号退出、技能启停、计划立即运行、发送或创建。外部文档、终端登录、Chatwoot 控制台、打开目录可能离开固定目标窗口，本轮未操作。
- 80 次上限使本轮没有逐点穷尽：原生菜单全部展开及无 chord 项、各表单所有字段/工具栏、账号卡片更多菜单、各渠道过滤器、长页下方所有服务商/语音模型、各工作区设置、全局技能预览/导入、脱敏四类执行流程、活动详情、爪形按钮和侧栏折叠等仍未验证。
- 不能把“看见入口”“进入页面”“功能执行完成”混用。后续扩展巡检从上述未覆盖项继续，不重复声称已经全功能验证。
