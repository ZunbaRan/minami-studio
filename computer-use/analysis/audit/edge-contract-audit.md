# Independent edge-contract audit — official Alma 0.4.164

Scope: data-only static inspection. No target app/code was executed. `M` below is extracted/Alma.app/Contents/Resources/cli/alma-computer-use-mcp.mjs (line references); `H` is analysis/host/main.pretty.js derived from extracted asar/out/main/index.js. Native addresses independently supplied by native analysis. These are original observable design boundaries, not recommendations to reproduce weaknesses. TCC is a separate OS permission layer; absence of an Alma app-approval check does not establish bypass of TCC or an attacker exploit.

## Verified contracts and corrections

1. **Cancellation suppresses MCP response; it does not prove native interruption.** Bundled SDK `_oncancel` aborts request controller (M33164–33167), `_onrequest` passes signal to handler and suppresses both success/error response if aborted (M33285–33367). Alma tool handlers ignore `_extra`, and DaemonClient.call has no signal/cancel path (M35799–35817). Timeout deletes pending ID and rejects only; a later response is ignored. No rollback or retry occurs. Native cancellation on disconnected client remains a separate question.
2. **Timeouts are layered, not one deadline.** Default daemon RPC 20s; `get_app_state` and post-action shot 30s. RPC timer starts AFTER ensureConnected. Connection attempts have no individual JS deadline; spawn retry loop aims at 4s with 100ms sleeps (M35818–35864). Approval/focus-warning HTTP fetches have no explicit timeout or abort signal. Host MCP client timeout is 600s (H35710–35720), while contextual outer watchdog defaults 300s (long task 14,400s; explicit positive timeout +15s capped 1,800s, H26185–26200). Outer watchdog races an abort signal and produces text claiming termination (H26258–26305); adapter execute ignores that signal (H35752–35761). Therefore watchdog completion is not native termination.
3. **Disconnect rejection is not cancellation.** MCP socket close nulls socket and rejects all pending with `computer-use daemon disconnected`; next call reconnects (M35877–35887). Host parallel manager does same with code `helper_disconnected` and notifies listeners (H16583–16600). Neither close branch clears shared `readBuffer`. A partial line can survive reconnect and corrupt/discard first new line: static hazard, requires runtime fixture. Malformed JSON and unknown IDs are silently ignored. `resp.ok` is a truthiness test, not exact boolean true (M35889–35901). Buffer accumulation has no visible max size in these clients.
4. **App approval is an advisory local layer with asymmetric coverage.** `checkApproval` immediately allows absent/falsy bundle, allows non-2xx HTTP or fetch/parse failure, and only denies successful parsed response whose approved is not exactly true (M35662–35682). Ordinary JS MCP `get_app_state`, list_apps, permissions, grant are ungated; launch and actions are gated, while sky_get_app_state is gated (M36041–36076 vs M36320 onward). PID-only/ref-only calls skip app approval. Host check_approval creates approval by default unless computerUseStrictApproval is exactly true; existing valid records bump usage (H72838–72867). HTTP action routes directly invoke Jp after PIP activity middleware, without calling check_approval in the route chain shown (H72905–72940). Host tool/plugin/project controls exist but are not a blanket per-app authorization layer.
5. **Approval denial is normal MCP content.** `gated` returns only content, no isError, no action log/PIP call on deny (M35729–35740). Successful inner execution is logged even if post-action screenshot failed. Warnings depend on cached focus_guard.arm_failures >0 (30s cache); failed permissions fetch clears warning flag. No warning does not prove focus protection.
6. **Ref outranks coordinate, action identity can differ from approval/capture identity.** Native MCP click/secondary chooses truthy ref, otherwise requires x and y not undefined; it sends ONLY ref plus options to native, not supplied bundle/PID/window (M36079–36155). Approval uses supplied args.bundle; post-shot uses normalized supplied target. Native owner confirmed AXBridge.click resolveRef at0x100013f6c→Entry.element (AX path0x1000141dc) or cached Entry.pid load0x100014364→EventDispatch.click0x100014388; secondary resolveRef0x100014654→cached PID dispatch0x100014804. Thus mismatched target/ref can operate on cached ref owner and approve/capture another app. This establishes inconsistent target binding, not exploitability. Scroll/set_value/select_text similarly send refs without supplied target, but native semantics for each must be confirmed separately.
7. **Schema validation precedes defaults.** SDK safeParseAsync returns parsed data or isError tool result (M34782–34801). Optional fields accept omission, not null. Descriptions saying bundle or PID required are not object-level refinements: all target fields optional (M36024–36028). Native click_count int max3 has no min; zero/negative passes schema then posIntOr→1. pages int max20 similarly defaults nonpositive→1; days int max90 defaults nonpositive→14. depth int max20 permits negatives then defaults→6; zero remains0. positive screenshot width retained, otherwise1280. Window/PID nonpositive omitted. Sky click_count has int but no max/min and forwards ??1; sky pages permits fractional/negative and forwards ??1. These surface differences matter for replication.
8. **Screenshot failure is degraded output, not action failure.** `respond` starts with success summary; absent target bundle/PID yields no post-shot at all, including window-only target. Valid target triggers get_app_state depth0 interactive_only true include_screenshot true maxwidth1280, with no auto_launch:false. Only local screenshot.path is read, MIME hardcoded image/jpeg. No path→unavailable text; any exception→failed text (M35930–35972). Native get_app_state output deletes screenshot metadata before JSON text, then reads path or reports screenshot_error; absent both is silently text-only (M36063–36076). No image-content validation here. Sky state instead returns screenshot.data_url or .url in JSON text, ignores path, no MCP image block (M36330+). Therefore native path-only screenshots do not automatically reach sky users as images.
9. **False-success/error-channel distinctions.** Most mutation wrappers ignore native response body and print success if RPC envelope ok is truthy; press_key alone checks delivered===false and emits NOT delivered text, still no isError (M36212+; sky equivalent). Bundled SDK converts thrown handler/native/schema errors into content plus isError:true (M34731–34778), losing error.code/hint from native in normal tool result. Host adapter `toModelOutput` recognizes thrown-call sentinel N but does not check MCP isError, so those tool failures become ordinary model content (H35762–35842). Qk may mark resolved error result as ✓ (H26305+). Receipt success must not be equated with effect success.
10. **Image capability guard has a name boundary.** Qk blocks /screenshot/i tool names and Read image extensions when visionInput!==true (H26244–26254). get_app_state/click are not matched by that name test. MCP adapter unconditionally maps image/audio to file blocks (H35785–35808); later provider conversion may still reject/drop them and must be tested. Do not conclude every model receives usable screenshots just because capture succeeded.

## Essential runtime acceptance matrix (not run)

- Cancel before approval returns, during native action, and during post-shot; observe actual side effects, response suppression, helper liveness, and whether a subsequent request succeeds
- RPC timeout then late native success; ensure no automatic action retry; host watchdog timeout while approval fetch hangs; SDK client timeout after outer watchdog already returned
- Disconnect with 2 pending commands and half a JSON line; reconnect then valid response; malformed line, unknown ID, out-of-order ID, truthy nonboolean ok, no newline / oversized line
- Strict approval: denied bundle, omitted bundle + PID, ref-only, get_app_state vs sky_get_app_state; API non-2xx, malformed JSON, stalled API; separately deny AX and Screen Recording TCC
- Same ref with matching/mismatched bundle+PID and coordinates; verify actual target, approved target, post-shot target, and log target; stale ref and ref from another app/session
- Missing target, window-only target, missing/empty ref plus x=0/y=0; null optional fields; zero/negative/max+1 values; native-vs-sky defaults; invalid element index
- Successful action + screenshot permission failure/missing path/read failure/wrong image bytes; delivered:false key; native result body with unsuccessful substatus but ok envelope; SDK isError to host/model receipt
- Vision-capable vs text-only/unknown model on click/get_app_state versus screenshot-named tool; sky raw path-only vs data_url screenshot

## Faithful behavior versus deliberate safe deviations

Faithful core: newline request-ID RPC, correct ref/coordinate transforms, per-surface schemas/defaults, TCC errors, async screenshot artifacts, host model-content conversion, recognizable degraded-image reporting, separate app/OS permissions.

Prefer deliberate documented deviations: bind approval/action/capture/log to one resolved target; fail closed for configured strict approval on unavailable approval service; propagate cancellation where feasible but report unknown outcome for already dispatched actions; never claim terminated without evidence; preserve isError/error code/hint and delivered:false; distinguish action acceptance from verified effect; enforce payload size and reset transport buffers on reconnect; gate images by actual content/model capability; do not automatically replay mutations after transport loss. These improve safety without pretending to be original behavior.
